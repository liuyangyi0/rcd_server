# RCD系统整体使用说明

日期：2026-10-21。供现场操作、OPC接入和软件维护人员使用。

本文说明现有软件分工和操作方式，不是实时在线清单。版本及状态以网页实际报告为准。带revision的SelectSource Method及数字开头状态输入已于2026-10-21随`0.6.12-state-names.20261021.1`发布到30、58、46；旧接口保留，详见[部署记录](../manager/docs/validation/state-input-digit-names-20261021.md)。

## 1. 先分清软件关系

```text
数据与业务操作
OPC客户端 ──4840──→ 所选OPC管理端 ──4841──→ 三台原采集程序 ──→ 串口设备/站点
                      （目前仅46）└──4842──→ 46新通信程序 ──→ 对方机组
浏览器 ──8087──→ OPC管理网页
                      └──内部运维请求──→ 目标机器RCD Agent ──→ 原采集程序启停

软件发布与管理端启停
浏览器 ──46:3000──→ Semaphore ──Ansible──→ 目标机器
                                         ├─ 升级/恢复管理端、原采集程序、Agent
                                         ├─ 通过systemd安全启停管理端
                                         └─ 恢复已停止的Agent服务
```

这是管理关系，不是所有程序都必须串行依赖的平台：Semaphore停止不停止现有采集；一个管理端停止不停止原采集，其他管理端仍可连接它。Agent是其下级唯一进程守护者，停止Agent可能影响其采集子进程，不应为排查普通站点故障随意重启Agent。

| 软件 | 负责什么 | 使用入口 |
| --- | --- | --- |
| Semaphore | 软件包、设备版本、升级/恢复、管理端安全启停 | 浏览器访问46:3000 |
| Ansible | 按平台任务连接目标机并执行受控操作 | 平台后台工具，操作人员不用单独登录 |
| OPC管理端 `RcdManager` | 汇总数据、分组选源、中央计算、配置/日志/运维、对外OPC | Web 8087；OPC 4840 |
| 原采集程序 `rcd_server` | 串口轮询、设备通信、控制命令与ACK、提供下级OPC | 在管理网页操作；下级OPC 4841 |
| RCD Agent | 守护并安全启停固定的一份原采集程序 | 管理网页的“进程”页；没有单独操作网页 |
| 新通信程序 `rcd_communicate` | 机组间串口快照收发、原名DATA变量及发送输入 | 当前经46管理网页配置；下级OPC 4842 |
| 外部OPC客户端 | 读取/订阅数据、选择来源、按协议提供命令或同步输入 | 连接所用管理端4840 |

新通信程序目前是独立服务，**未接入平台的三组件一键发布、Agent安全启停或原采集的全部运维能力**。不要因为能在管理网页编辑它的配置，就认为它已经能在同一页面安全重启、查看全部日志或查询采集站点。

## 2. 打开哪个地址

| 机器 | 管理网页 | 对外OPC | 原采集OPC |
| --- | --- | --- | --- |
| 30 | `http://192.168.10.30:8087` | `opc.tcp://192.168.10.30:4840` | `opc.tcp://192.168.10.30:4841` |
| 58 | `http://192.168.10.58:8087` | `opc.tcp://192.168.10.58:4840` | `opc.tcp://192.168.10.58:4841` |
| 46 | `http://192.168.10.46:8087` | `opc.tcp://192.168.10.46:4840` | `opc.tcp://192.168.10.46:4841` |

- 软件运维平台只有一套：`http://192.168.10.46:3000`。
- 新通信下级：`opc.tcp://192.168.10.46:4842/`，当前接入46管理端；串口仍停用。
- 外部OPC客户端正常接入4840，不绕过管理端直连下级。
- 两个网页各用自己的已有账号；Web登录与OPC认证分开。账号密码由管理员提供，本文不保存密码。

三台管理端相互独立，不是自动主备集群。业务组、默认来源、在线Session选择和计算配置不会因为登录另一台管理端而自动同步；切换管理端地址会建立新的Session，需要重新核对配置和选源。

现有原采集来源稳定ID：30=`rcd-30`，58=`rcd-58`，46=`rcd-46`。新通信来源ID=`communicate-46`，通信组ID=`unit-sync-46`。IP是连接地址，显示名称可改，稳定ID不能用显示名称替代。

## 3. 每天先检查什么

1. 打开所用管理网页，确认“管理OPC运行中”。
2. “下级OPC”检查目标来源的连接、Session、订阅和目录；Agent状态在该来源“运维 → 进程”查看。
3. “点位浏览”检查实际业务变量的值、质量和源时间，不只看来源连通。
4. “告警与审计”查看未处理的软件、通信和差异告警。
5. 需要发布或启停管理端时，再进入Semaphore；普通读数不需要运维平台参与。

| 状态 | 表示什么 | 不表示什么 |
| --- | --- | --- |
| 平台“检查成功” | 运维检查任务执行成功 | 所有设备通信正常 |
| 程序“运行中” | 已确认目标进程运行 | 每个串口都能打开 |
| 下级OPC已连接 | 管理端与下级OPC通道可用 | 物理站点都正常 |
| Agent不可达 | 进程运维通道不可用 | 下级一定已崩溃 |
| 业务质量Good | 当前值按该业务接口有效 | 命令动作已完成 |
| 历史快照/过期 | 显示上次确认数据 | 实时在线证据 |

## 4. OPC管理端怎么用

### 4.1 看数据和定位来源

进入“点位浏览”，搜索变量名，按逻辑组、目录成员、串口、设备或质量筛选。分页只加载当前页，导出使用当前筛选。

- “当前默认源”显示各组默认来源的数据。
- “指定在线Session”显示目标OPC客户端实际采用的路由。
- “指定来源（诊断）”用于检查某下级，不改变默认源或客户端选择。
- “目录成员”只限制点位清单，不等同于切换样本来源；需要诊断某来源的值时，应同时明确样本路由。

### 4.2 配置来源和逻辑组

在“下级OPC”维护来源名称、Endpoint和安全参数；Agent绑定入口是“目标来源 → 运维 → 进程 → 编辑守护绑定”。启用统一机器台账时，绑定由台账同步管理，不在来源Endpoint表单内修改。新增来源后先等待目录发现完成，检查冲突和点数。

设备归组分两处操作：

1. 在“分组与选源”建立逻辑组。
2. 在维护窗口暂停控制，结束管理端全部在线OPC Session，并等待相关命令完成；有在线Session或待处理命令时不允许保存映射。
3. 在“下级OPC → 目标来源 → 串口 / 设备映射”将对应物理站点绑定到该组，逐一完成所有冗余来源的映射。
4. 分步保存时可能暂时出现跨组目录冲突；完成对应映射并确认目录恢复后，再接入客户端。

不要把不同设备仅因变量同名就合并；同组同名还要求类型、值秩等兼容。冗余来源的旧共享命令节点应保留在相同兼容默认组。跨组重复或类型冲突会隔离相应目录，不能靠改显示名称解决。

一次选源作用于一个Session中的整个逻辑组；要让两个站点能独立切源，应先配置为独立逻辑组。站点、版本、配置和进程操作始终针对固定物理来源，不随客户端选源改变目标。

### 4.3 手动选源

Web操作：

1. 客户端先连接4840。
2. 在“分组与选源”选择目标在线Session，核对客户端名称和Session ID。
3. 选择逻辑组，打开切源操作，核对目标来源和设备对应关系后确认。
4. 回到目标客户端确认来源和质量。不要只在另一个测试连接上读回。

修改“默认来源”只影响之后新建的Session；在线Session要单独切换。中央计算使用默认来源，所以修改默认源可能改变计算结果。

`MemberSourceIds`列出已配置成员，含离线、停用及不可选来源。另查成员的Selectable、ConnectionState、CatalogState和CompleteCoverage；“可选”不等于“在线”。

新增OPC选源Method在部署后可用，详见第8节。旧SelectedSourceId String写入继续保留，但不携带客户端期望revision。

### 4.4 自动切源和差异告警

入口：“分组与选源 → 目标组的‘自动切源 / 差异告警’按钮”，打开配置弹窗。两项独立，默认关闭。

- 自动切源：配置优先级、故障确认、备用健康确认和冷却时间；已有Session需明确设为“跟随自动”。没有健康备用时保持原选择，不自动回切。
- 手动选源（Method或旧Write）会把本Session本组改为“手动固定”。
- “组默认来源也自动切换”单独控制默认源和中央计算，不等同于接管全部Session。
- 差异告警：选择两个可比较来源，配置持续时间和容差；坏质量、缺点、时间不匹配不能伪装成数值差异。差异不能证明哪一方正确，也不直接触发切源。

新通信程序的数据同步不具备旧采集站点的全部健康能力，不能照搬原采集自动切源策略当作冗余发送主备。

### 4.5 计算中心

1. “规则配置”从文件或下级导入calc.toml，保存草稿。
2. 校验并修正错误，再激活；校验失败仍运行上一有效版本。
3. “实时结果”按变量、类型、质量筛选，检查表达式、值、错误和求值时间。
4. “版本历史”可把历史配置恢复为新版本，不抹掉历史。
5. “下级模式”切为manager后需明确重启下级；本地calc.toml保留为回退副本，但不再执行。

普通原始采集输入按各组**默认来源**取数，生成一份共享计算结果，Session单独选源不改变它。“计算中心 → 状态输入”还可将通信状态绑定到固定物理来源，或跟随组默认来源。状态输入激活后直接生成`ns=2;s=<name>`同名只读UInt32节点，不必再写转发公式；也可继续在公式中引用，见[状态输入说明](../manager/docs/guides/calculation-state-inputs.md)。

原始采集输入为BadNoCommunication时按0参与计算，质量只沿实际执行路径传播；最终结果不一定为0。IF未执行分支的坏质量不污染结果，纯常量也不因无关来源离线变坏。状态输入的“离线=5”可以是有效的Good诊断值，不能与原始采集值一律清零。客户端须同时检查值和质量。本系统不保存计算历史曲线。

## 5. 原采集程序怎么用

### 5.1 开关串口或站点读取

入口：“下级OPC → 固定目标来源 → 运维 → 采集”。

1. 核对来源、物理串口和站点。
2. 修改串口启用或站点读取开关。
3. 等待worker应用，分别检查期望值、已应用值、串口实际打开状态及通信状态。

关闭串口不停止下级OPC服务；停读站点不等于停止整个进程。站点停读也不能当成禁止所有控制命令的安全开关。

### 5.2 修改配置

入口：“运维 → 配置”。

1. 选择config.toml、CSV点表等下级公布的文件。
2. 使用参数表单；复杂结构/CSV使用原文编辑。下拉选项按实际枚举选择。
3. 点击“生成配置草稿 → 校验当前草稿 → 保存到下级”。校验不是保存。
4. 保存后按提示明确重启下级，确认磁盘配置与运行配置一致。

常用参数：

| 参数 | 含义 |
| --- | --- |
| settings.command_retry_count | 命令最大**总发送次数，包含首次**；3表示最多发3次，不是补发3次 |
| settings.query_retry_count | 普通轮询失败后的补发次数 |
| settings.timeout | 串口读取超时，毫秒 |
| settings.poll_interval_ms | 轮询间隔，毫秒 |
| settings.parity_switch_delay_ms | 校验位切换保护，毫秒 |
| settings.transmit_settle_guard_ms | 发送完成保护，毫秒 |

波特率、校验、站点地址及点表必须与实际设备一致。配置冲突时刷新比较版本，不覆盖其他人的修改。备份只先载入草稿，再校验和显式保存；不能用历史配置覆盖当前文件来“只恢复软件”。

### 5.3 启动、停止、重启下级

入口：“固定来源 → 运维 → 进程”。管理端通过该来源绑定的Agent执行，不靠下级OPC重启自己。

1. 核对物理目标和影响范围，暂停相关控制请求。
2. 提交一次启动/停止/重启。
3. 等待排空、执行与验收；结果不明确时查询原作业，不重复点击另建任务。
4. 确认进程、OPC及采集恢复；物理故障单独处理。

这会影响使用该物理来源的所有组和客户端，不只影响发起页面的Session。人为停止意愿会保存，升级后不应擅自拉起原本停止的程序。

Agent不可达时先在Semaphore检查或恢复Agent服务。不要删除进程状态、维护记录或锁文件绕过“忙碌/待确认”。

### 5.4 查看日志、命令和设备版本

- “下级日志”：搜索已HTTP推送到本管理端的日志。只会推到配置的接收端，三台管理端不会自动互相复制日志。
- “运维 → 日志”：读取目标下级的本机日志，用于核对推送缺口。下级停止时OPC文件读取可能不可用，进程输出另看Agent记录。
- 日志等级：日常INFO，排障短时DEBUG/TRACE。保存等级后按页面提示重启；环境变量覆盖时以页面实际运行值为准。
- “命令记录 → 执行过程”：看固定目标、排队、下级尝试次数、完整写出次数、ACK及终态。审计不完整表示证据有缺口，不是发送0次。
- “设备版本”：按来源/串口/站点设置国产、俄供或未知类型，查看通信模块和PLC版本。只有已确认国产且启用的站点可发查询；俄供/未知不查询。此功能可能产生实际串口请求，不是纯读软件版本。
- “系统信息 → 软件版本”：查看当前管理端及其全部下级/Agent的软件身份；设备模块版本和软件版本是两回事。

### 5.5 Agent怎么使用

Agent没有供日常操作人员直接登录的网页；它通过固定实例配置管理一份原采集程序。平时使用上面的“进程”页，不手工重复启动第二个采集进程，也不通过HTTP临时指定任意程序或命令。

查看Agent连接、实例身份、下级期望状态和实际进程；Agent自身的软件升级/兼容恢复走Semaphore。Agent已停止时用平台“恢复Agent服务”，不是让下级或Agent自行启动自己。原本人工停止的下级应保持停止，维护结果未知时先补查原作业。

## 6. 新通信程序怎么用

用途：机组间双向数据同步，不是原采集轮询，不生成“查询命令”等待逐站回复。

当前46为1号侧示例：接收9→1的15个变量，发送1→9的39个输入，另有4个辅助节点，共58项。角色与独占串口尚待现场确认，全部串口/任务/发送继续停用。出现BadOutOfService是当前预期。

### 6.1 配置

入口：“46管理网页 → 下级OPC → communicate-46 → 运维 → 配置”。

改变角色、任务与点表时，选择configuration-set.toml成套视图，同时修改config_toml与points_csv，再校验、保存。它是两份配置的联合视图，不是第三份运行文件。不要只换程序而继续加载旧点表。

保存不重启、不启用串口。目前不具备Agent安全启停和平台一键发布入口，需维护人员在明确窗口处理独立服务；不能照搬原采集进程按钮。

### 6.2 客户端读写

客户端仍连接46管理端4840，使用原文档名称：

```text
接收示例：ns=2;s=DATA.Buildings.91UBH.Fire   UInt32，只读
发送示例：ns=2;s=DATA.Buildings.11UBE.Fire   UInt32，读写
整包入口：ns=2;s=TransmitSnapshot           String，读写
发送状态：ns=2;s=TransmitStatus             String，只读
```

Fire编号：0未知（仅接收）、1正常、2红色报警、3红色报警闪、4黄色报警、5黄色报警闪、6故障报警、7故障报警闪、8闭锁。原始AES/GMM/HW/泵站块仍是定长十六进制String，不套用Fire编号。

发送方式任选一种：

- 逐点：首次写齐39项，无变化每5秒刷新全部，有变化立即写相应项；同一次多节点Write不保证整包原子性。
- 整包：读取TransmitStatus.revision，将完整39项JSON作为String写TransmitSnapshot；成功后进程进入atomic模式，不再接受逐点拆写。后续同样周期提交完整包。

15秒内任一必需输入没有成功刷新就停止整包发送。刷新、过期时间可配置；客户端读取InputRefreshIntervalMs和InputTimeoutMs，不永远写死5/15秒。

OPC写入成功只代表缓存接受；complete_writes增加代表本程序完整写出串口帧，不证明对方收到。此接口没有00 50 50 ACK，不进入原采集_Send FIFO；它发送最新快照，不保证每个中间变化逐条发出。

完整变量清单、单点和39/14项整包示例见[通信OPC客户端说明](../communicate/docs/opc-client-guide.md)。切源不会撤销旧来源已接受的快照，不可用选源接口替代独占发送权或停止发送。

## 7. Semaphore和Ansible怎么用

### 7.1 检查版本

进入“设备与版本”，选择机器查看三个组件的运行状态、实际运行版本及磁盘版本。“刷新”只更新已收到的信息；“检查状态”才新建只读检查任务。离线时显示最后快照，超过有效期会标记过期。

### 7.2 升级软件

1. “软件包 → 上传软件包”，上传已构建的单组件*.rcd.tar.gz。
2. 确认组件、版本、架构及校验通过。包里不应包含现场配置、数据库、日志、密码或PKI；上传不会安装。
3. “升级软件”下拉选择组件、版本和目标机器。
4. 核对重启影响，确认本次已暂停相关控制命令，再执行一次。
5. 多机按30→58→46串行；看“升级任务”的每台结果和日志。
6. 完成后看实际运行版本、OPC/HTTP及业务采集；任务Success不等于所有物理站点正常。

日常不用手工填写服务器路径、哈希、脚本或Ansible命令。普通升级支持下级OPC、OPC管理端、RCD Agent；新通信程序和平台自身升级不冒充已接入该三组件入口。

### 7.3 恢复版本

入口：“设备详情 → 组件 → 版本历史 → 恢复此版本”。这是一次新任务，不改写原升级历史。只恢复兼容的程序，保留当前配置、数据库、PKI和维护状态；不兼容版本应禁用并说明原因。

失败自动恢复、主动恢复旧版本、灾难数据库恢复是不同操作。结果待确认或恢复失败时保留现场，补查原事务；不要更换任务号反复升级，不删除锁，不随意覆盖旧数据库。

### 7.4 启停管理端、恢复Agent

- 管理端：“设备与版本 → 查看详情 → OPC管理端 → 启动/停止/重启”。不需要先选软件包；先排空控制事务，再操作目标服务。重启会断开其OPC客户端，不停止远端下级或其他管理端。
- Agent：“设备详情 → RCD Agent → 恢复Agent服务”。只用于已确认停止的服务；Agent异常可能影响本机下级，需核对原作业和停止意愿。
- 下级日常启停仍去管理网页的Agent进程入口，不保留第二套普通启停按钮供人误选。

“高级管理”中的库存、凭据、仓库、模板和计划由维护人员配置。Ansible复用平台队列执行，不是另一套需现场人员反复点“分发、部署、验收”的日常流程。

## 8. 外部OPC客户端怎么用

1. 连接所用管理端4840，按现场要求信任证书及选择身份。
2. 浏览Objects/Devices，读取或订阅Value，同时显示StatusCode与SourceTimestamp。
3. 在Objects/RcdManager/Groups确定变量所属组，检查成员与当前Session选择。
4. 新客户端优先使用带revision的选源Method；不支持Method的旧客户端继续写SelectedSourceId。
5. 按业务区分原采集控制命令和新通信同步输入，不能共用一种成功判断。

### 8.1 带revision的选源Method（本次新增，部署后可用）

```text
ObjectId：ns=3;s=Groups/<组ID>
MethodId：ns=3;s=Groups/<组ID>/SelectSource
输入0：SourceId，String，目标稳定来源ID
输入1：ExpectedRevision，UInt64，本Session刚读取的SelectionRevision
输出0：SelectedSourceId，String
输出1：SelectionRevision，UInt64
```

例如读到SelectionRevision=10，提交目标来源和UInt64 10；成功输出本次选择及11。若Web已先更新到11，旧请求返回BadInvalidState，不改变来源。重新核对当前意图，不自动套用新revision重试旧选择。组有在途事务时返回BadWaitingForResponse。

旧String写入不含客户端期望版本，读Revision后再普通Write也不能防止陈旧意图覆盖。选源、读数和业务写入必须属于同一Session；新Session重新从默认源初始化。两个revision不要混用：SelectionRevision用于管理端路由，TransmitStatus.revision用于下级发送快照。

### 8.2 原采集控制命令

只向经过确认的_Send String或对应_SendCommand Method提交已核准报文，不为测试随意生成设备动作。

- _Send变量写入按固定来源和物理串口FIFO接受，容量64含执行中；相同报文不自动合并。接收/入队不等于执行成功。
- 同步Method的调用结果按其协议返回，不应假定所有Method也能无限排队。
- 查看对应结果节点或命令记录的最终状态、ACK与审计明细。有效00 50 50表示协议确认后停止重试，不证明设备动作反馈已核实。
- ACK超时、断线或结果不明时，不换来源自动重投；设备可能已收到但回复丢失。

## 9. 出问题先查哪里

| 现象 | 首先检查 |
| --- | --- |
| 管理网页打不开 / 客户端4840断开 | 平台中的目标管理端进程、HTTP/OPC及实际运行版本 |
| 下级OPC断开 | 目标来源进程、Agent状态、Endpoint、证书和网络；不直接判定串口卡损坏 |
| 下级OPC在线但站点坏质量 | 串口开关、实际句柄、站点读取、超时及原始日志 |
| Agent不可达，无法启动下级 | 平台检查/恢复Agent，不让已停下级通过自己的OPC启动自己 |
| 选源成功但订阅未变化 | 是否同一Session、选中哪个组、实际质量；同值也可能是正确结果，订阅刷新为异步 |
| 整包BadInvalidState | 是否误用SelectionRevision、是否读到旧缓存、是否有另一写入者；不盲目重复提交 |
| 新通信变量BadOutOfService | 当前串口/任务/发送仍停用，属于已知边界，不自行启用消警 |
| 有日志推送但另一管理网页为空 | 推送只配置到哪个接收端，筛选是否过旧；三管理端不自动同步日志 |
| 任务“结果待确认” | 补查原编号和目标维护记录；不重复升级、不删锁文件 |

## 10. 文件与备份保留什么

程序入口在/opt/rcd/bin，生效配置和数据在/var/lib/rcd，日志在/var/log/rcd；旧home/code工作目录通常是构建、验证或历史副本，不能随意从那里再启动第二个实例。

备份至少保留：当前配置和点表、计算活动配置、数据库的一致性备份、PKI、Agent/维护/命令状态及日志。不要把程序更新等同于覆盖用户配置；不要删除锁、停止意愿或事务文件“清除故障”。
