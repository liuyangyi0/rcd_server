# Semaphore UI（RCD 运维入口）

Semaphore 是软件发布平台，不替代管理 OPC 的业务 Web，也不是高可用主备控制器。当前使用固定 Community **2.19.16** 的原生 Vue/Go 定制版本；独立 SQLite、非 root 服务账号和 systemd 不变，没有门户或 iframe，不修改 OPC 端口。

2026-10-08：原生定制版已上线 **46:3000**，保留原账号、加密凭据与任务历史。源码及验证入口见 [custom/README.md](custom/README.md)。Mender 迁移暂停，原 `operator-ui` 不恢复。

## 当前网页怎么用

1. 登录后进入“RCD 运维”，默认显示“设备与版本”。一台机器一行；“刷新”只读取保存的数据，“检查状态”才提交只读检查任务。每分钟自动检查一次，同设备未完成的检查不会重复排队。
2. “软件包”右上角选择“上传软件包”，上传构建器生成的单组件 `*.rcd.tar.gz`。自动识别下级 OPC / OPC 管理端 / RCD Agent / 串口通信程序、版本与平台；上传不会安装。不是直接上传 EXE，也不上传配置、数据库或 PKI。上传成功后可直接“选择设备升级此软件包”；详情也有相同入口，已停用的重复包不会被自动启用。
3. 点击“升级软件”，下拉选择组件和版本，再选择机器。`rcd.7`起可在向导内“检查此设备状态”及“刷新设备与兼容性”，不必退出向导；前者创建原生只读检查任务，后者只读取结果，都不重启程序。确认框按实际执行顺序显示目标及受影响程序；当次暂停控制命令后勾选确认并执行。多机按 **30 → 58 → 46** 串行，失败或结果未知时不继续。更换目标/软件或刷新状态后需要重新勾选；版本冲突不自动再次发布。
4. “操作任务”查看每台机器的阶段、结果和原生任务日志。`rcd.7`起详情内可“刷新任务详情”，只读取原任务；读取失败时标注保留的历史结果，成功恢复后清除错误。只有软件验收与运行映像匹配才显示成功；这不代表每个串口设备正常。
5. 需要恢复时，进入“设备详情 → 组件 → 版本历史 → 恢复此版本”。它创建新任务，保留原历史；仅恢复程序，保留当前配置、数据库和维护状态。不可兼容的版本会显示禁用原因，不要求填写备份路径。历史列表统计安装记录，不等于不重复的版本数；`rcd.7`起会阻止误点恢复已是当前实际映像的记录。数据库schema相同不代表旧程序支持新配置语法，恢复前须确认。
6. 任务结果待确认时用“补查原事务”，不要重复创建升级或删除目标机维护记录。补查不重新部署。恢复失败交给维护人员处理。

“已停止”没有运行版本；“磁盘与运行版本不同”表示新文件尚未成为运行程序；超过 180 秒的报告显示过期。页面不能实时证明设备在线，也不能把 Ansible 的 `Success` 当作采集正常。

设备列表显示CPU、内存和磁盘摘要；详情可查看网卡地址、链路、累计流量及短窗口速率。指标沿用每分钟原生巡检，不是实时监控，采集失败不填0。

新增主机使用“设备与版本 → 添加主机”：选择原生加密SSH/sudo凭据、核对主机公钥指纹，再执行检查与登记。新软件类别使用“软件包 → 添加软件种类”，登记后才能上传该类别的版本包。首次安装与普通升级分开，安装后保持停止、待配置，不自动启用串口。操作步骤、前置条件和单二进制支持范围见[主机与软件使用说明](../../../manager/docs/guides/platform-hosts-and-applications.md)。

原生模板、库存、仓库、凭据和计划收在“高级管理”。旧发布模板的运行按钮进入同一发布表单，不能绕过包校验。普通操作不再需要 SSH、手填服务器路径或人工登记软件包下拉选项。

### 维护文件与备份

- 上传目录：`/var/lib/semaphore/rcd-packages`；仅平台服务及维护人员可访问。
- 受控脚本快照：`/opt/semaphore/rcd-platform/<摘要>`；原生仓库绑定不可变快照，不修改正在执行的版本。
- 内置组件固定发布配置：`/etc/rcd/release-platform/{lower,manager,agent,communicate}.json`；程序仍在 `/opt/rcd/bin/`，未安装的组件不会因此自动生成配置。自定义软件使用固定 `/opt/rcd/apps/<软件ID>/` 和用户服务，不接受包内自定义安装脚本或任意路径。
- 平台升级使用 `custom/install_platform.py`，一致性备份数据库、配置/加密密钥、包及原程序；失败必须配套恢复数据库和二进制。新版本数据库不能只换回旧程序。
- 首次接入用 `tools/release/bootstrap_platform.py`，需要当次维护窗口；只补齐旧程序缺少的维护能力，不作为日常升级器。已有接入状态会拒绝重复执行。
- 新设备绑定使用 `custom/onboard.py`；每分钟检查由原生计划建立，重复登记不额外创建计划。
- 包生成使用 `tools/release/rcd_package.py`；公开清单、校验与命令见 [格式规范](../../../contracts/release-package/README.md)。旧包只做校验导入，缺少维护接口的历史版本停用归档，不冒充可一键恢复。

业务 Web 仍是三台各自的 `8087`，管理 OPC `4840`、下级 OPC `4841` 不变。软件、串口/站点是不同健康层次。

`bootstrap.py` 创建“RCD 运维”项目、加密 SSH 凭据和 30/46/58 各一条只读巡检模板：查看服务、运行映像和版本。任务串行执行，保留完整任务输出。主机密钥检查开启；30/58 沿用已信任的主机公钥，46 使用本机 SSH 公钥。

原生页面会记住当前浏览器上次选择的分类；若仍停在 `All`，点击上面任一分类。旧 `/operations` 定制页面书签不再使用。

表格右上角齿轮可取消“版本、剧本、库存、变量组、仓库”列，只保留名称、执行入口、状态、最后任务。**这些偏好仅保存于操作人的当前浏览器，不是服务端统一设置。** 普通任务的“版本”列可能只是结果图标；`Success` 仅表示该次任务成功，预检成功不等于软件已经升级，也不代表设备通信正常。

软件升级：

1. 打开对应机器的“软件升级”，点“运行”。
2. 下拉选择组件和软件包。三台机器均有管理端；Agent 重启会同时影响它管理的下级。
3. 默认“仅检查，不重启”，可直接执行检查。
4. 真正升级时选择“确认执行”，并在实际暂停所有管理端、直连客户端控制命令后选择“已暂停”。后台自动分发、检查、备份、替换、重启和验收，不需要逐个执行这些步骤。
5. 查看任务日志；`recovery_backup` 是本次替换前的一致性备份路径。

版本回退：打开对应机器的“版本回退”，选择组件，从原升级任务日志复制 `recovery_backup` 完整路径。默认只检查；确认暂停命令后才执行。普通回退保留当前配置和数据。数据库版本不兼容或上次操作结果不确定时会拒绝继续，须由维护人员处理，不要反复点击或擅自覆盖数据库。

当前软件包 `rcd-standard-paths-20260928` 是已有来源摘要、二进制哈希的现网版本，可重装，不代表又构建了一个新版。软件包仅包含程序与构建清单，不下发现场串口配置、数据库或 PKI。新增已验证版本后由维护人员更新包目录及下拉选项。

## 接入配置（维护人员）

`connect_release.py` 复用现有发布器，不实现另一套服务控制。命令分别负责：

- `prepare-target --target 30|46|58`：在所选目标机生成固定路径 profile，不操作服务。配置目录在每次发布时枚举，保留使用人后来新增的文件。
- `export-catalog`：在 46 核对现网程序与原发布清单后，登记可分发包。
- `install-snapshot --source <绝对路径>`：无平台任务运行时，一致性备份平台数据库和旧脚本，安装运维脚本快照。不重启业务服务。
- `register`：建立/更新六条升级、回退模板。`SEMAPHORE_ADMIN_PASSWORD` 使用当前密码；首次登记 sudo 凭据时使用进程环境中的 `RCD_NODE_PASSWORD`，不写进脚本。

目标绑定：`/etc/rcd/release-profiles/`；目标包及备份：`/var/lib/rcd-release/<组件>/`；控制器包目录：`/opt/semaphore/artifacts/`；目录清单：`/opt/semaphore/catalog/releases.json`。平台以非 root 运行，发布通过加密凭据执行 sudo；用户级服务明确切回所属用户的 systemd 总线。没有放宽程序文件权限。

`verify_release.py` 只提交“仅检查”；`browser-release.cjs` 检查表单并提交一条未确认的只检查任务，不升级。异常事务恢复仍使用现有发布器的维护命令，不作为现场日常菜单。

## 安装与维护

`install.py` 是有保护的首次安装工具，不是覆盖升级脚本。要求 root、明确本机地址、已经下载并校验的官方包，以及已验证的 Python/Ansible 工具目录。发现现有平台目录/服务账号会拒绝覆盖。只控制新 `semaphore.service`，不调用 RCD 服务启停。

`bootstrap.py` 使用官方 API 建立项目；节点 SSH 密码仅从安装进程的 `RCD_NODE_PASSWORD` 环境变量读取。相同名称的已有对象保留，不自动改写管理员手工修改的配置。

常用检查：

```sh
systemctl status semaphore.service
systemctl is-enabled semaphore.service
journalctl -u semaphore.service --since today
/opt/semaphore/bin/semaphore version
/opt/semaphore/venv/bin/ansible-playbook --version
```

升级或迁移平台前应对 SQLite 做一致性备份，并单独保护 `config.json` 中的加密密钥；丢失密钥会导致已存 SSH 凭据无法解密。不要只复制运行中的 SQLite 主文件。平台与业务 RCD 的升级是不同操作。

当前使用受信内网 HTTP；它不是传输加密。不要直接映射到公网。如需跨不可信网络访问，应另行配置 HTTPS/反向代理。

官方参考：[Community 发布包](https://github.com/semaphoreui/semaphore/releases/tag/v2.19.12)、[非 root 服务与 systemd](https://semaphoreui.com/docs/admin-guide/installation_manually)、[该版本 API 契约](https://raw.githubusercontent.com/semaphoreui/semaphore/v2.19.12/api-docs.yml)。
