# 协议与业务点接入

本文件说明适配器扩展边界。已实现的机组同步详见 [同步协议与使用说明](unit-synchronization.md)。不能将测试中的 `01 02 03`、`expected` 或工作表捕获值发到现场冒充本方数据。

## 1. 已固定的扩展边界

`DeviceProtocol` 只负责 CPU 逻辑，无文件、网络或串口 I/O：

```rust,ignore
fn request(&mut self, task: &TaskConfig) -> Result<Vec<u8>, ProtocolError>;
fn response(&mut self, task: &TaskConfig, payload: &[u8])
    -> Result<Response, ProtocolError>;
```

`request` 返回未压缩载荷，串口事务应用原有 zlib/长度/CRC32 包络；如果真实设备不是这个包络，需要在接入前明确调整，不能仅更换字段映射。

`response` 收到已经验证包络的载荷，仍必须核对设备地址、功能码和响应关联。无关响应返回 `Ignore`，仍在同一总超时内等待；本事务完整响应返回 `Matched(Vec<PointUpdate>)`。匹配但非法的载荷返回错误，不得用部分数据刷新 Good。

`Matched` 必须覆盖该任务点表中的全部 KKS、恰好一次、类型一致。数组、NaN、无穷值和过长字符串被拒绝；整批不匹配时不发布任何一个 Good 值。设备没有可信时钟时用接收时间，不生成伪造设备时间。

正式适配器在 `production_registry()` 编译期注册，不能由网页上传任意脚本或命令。现已注册 `unit1-to9-v1` / `unit9-to1-v1`。它们的 `unsolicited()` 返回 true，使用持续流同步而不是 request；配置检查和运行入口使用同一注册表。

## 2. 轮询与控制必须区分

- worker 根据适配器区分查询与主动同步；每个物理串口一个所有者，其他模块禁止直接读写。同步端口只配置一个接收布局，不能混入查询任务。
- 周期性查询失败后不立即重发；下一周期是新的只读查询。**不得把有副作用的写命令放进周期任务**。
- 部分写入失败保留已写出字节数，只续写剩余部分；发生错误结束本次交换，不从头发送整个报文。
- 每次交换使用新解码器，超时后有限隔离和清缓存。隔离窗口不是无限迟到响应的关联保证：若协议没有事务号或等价字段，必须明确它无法证明设备“恰好执行一次”。
- 未来控制命令需单独的单次请求入口、端口互斥、固定目标、在途状态、明确 ACK/超时及审计；不能复用轮询自动重复。
- 不把原 RCD 的 `00 50 50` ACK 或重试次数套到新设备上。

## 3. 用户稍后提供的资料

| 资料 | 用途 |
| --- | --- |
| 每类查询的发送十六进制、响应十六进制（最好多组） | 建立黄金报文测试，区分帧与载荷 |
| 站点地址/功能码/序号字段、主动上报规则 | 判断响应属于哪个任务，过滤无关与迟到数据 |
| 各字段偏移、长度、大小端、有符号性、浮点格式、倍率、单位 | 解析真实数值，不猜测 |
| KKS、OPC 类型、字段无效条件及质量含义 | 生成只读点表和质量规则 |
| 串口路径、波特率、校验位、停止位、允许的查询频率 | 确定现场配置及容量 |
| 是否首字节分发、字节间延迟、最大响应时间、最大帧长 | 确定发送时序及超时预算 |
| 如需控制：发送内容、应答、幂等性、是否允许重试 | 独立设计控制事务，不混入轮询 |

## 4. 后续接入顺序

1. 在本模块增加真实协议适配器、点表和黄金报文测试，显式注册协议名。
2. 在 46 隔离目录进行帧、字段、质量、异常及 OPC 互操作测试；软件桩不能代替硬件验收。
3. 确认实际串口归属、空闲端口及运行目录，避免与现有 RCD 抢串口；取得当次现场接入授权。
4. 部署为独立采集实例，以明确新 source_id 接入管理端，验证 Browse/Read/Subscribe 与分组/重名检查。
5. 按新实例身份补齐 Agent/平台的受控启停与发布；不得替换原 Agent 唯一守护的老 RCD 实例来冒充接入完成。
