# 命令审计补查与来源统一（2026-10-09）

## 范围与原因

本次获准在控制命令暂停期间修复并部署 30、58、46 管理端，统一来源定义；不重启下级或 Agent，不发送硬件控制命令，不改串口时序及 ACK 判断，不提交或推送。

46 管理端截图中北京时间 2026-10-08 17:00:42、17:03:59、17:05:36、17:06:40 的四条 ttyWCH5 命令，按管理实例和命令编号核对下级独立审计：均调用发送 3 次、完整写出 3 次，三次均 ACK 超时。管理端对应 snapshot 为 NULL、revision 为 0，来源游标停在 577，并持续报告审计写入超时。

根因链路：单条补存复用来源级缺口更新，会在 100 ms 预算中反复更新整段历史；事件游标又依赖所有来源的内存脏记录清空，导致补查停滞。已经结束的命令没有独立补查路径。58 的重复物理来源还会让其他逻辑来源的事件触发目标不匹配。

## 修改

- 来源级缺口只在批次提交时更新，并只修改尚未标记的行；单条补存不再改写整段历史。
- 只提交当前批次的相关缓存身份、执行证据及游标，不等待其他来源。并发的新状态仍保持待落盘，不能因旧批次提交而清除。
- 分批遍历缺少/未结束的历史快照，按固定 gateway、boot、port、请求摘要及 command ID 只读补查；终态补查不改写原管理端超时/失败结论。
- 共享下级的非本来源事件不改绑、不阻塞本来源游标；来源 IP 修改后，可借助仍连接原 gateway 的来源补查原历史，保留旧记录的身份。
- 区分“下级审计不完整”和“已取得执行快照，但历史中间事件可能缺失”，未知次数不写成零。
- 下级列表显示机器名称及稳定 ID，并支持按名称搜索。
