## 新功能：下级控制命令最小间隔

```toml
[settings]
command_interval_ms = 500 # 配置片段示例，不是自动应用到现场的默认值
```

范围 `0..60000` 毫秒，缺省 `0`。一台采集下级配置一个值，每个物理串口独立使用单调时间计时：**上一条控制事务完成后，到下一条不同命令首次发送前**至少等待此间隔。首条无需人为延迟，实际派发还会受到当前串口交换时长影响。

- 放在下级唯一串口 worker，不只在某一管理端队列中 sleep；多管理端、旧 OPC、TCP 控制入口共用这一执行边界。
- 冷却期间原 FIFO、载荷及维护 permit 保留；继续普通轮询、备机监听及满足准入条件的版本查询，无额外串口读写线程。
- 同一命令内部重试次数、时序和 `00 50 50` 判断不变；有效 ACK 立即结束重试。
- 过期命令不发送、不重置冷却；串口重连、worker 恢复不能绕过现有冷却。停用和退出按原作业边界失败清理，不等完整冷却时间。
- 等待计入原期限，不延长管理端队列总期限或短调用期限。间隔过长、积压过多会明确超时，不无限保存、过期补发或自动重试。
- 新版采集的 `prepare_config` 自动暴露“控制命令最小间隔(ms)”，现有管理网页参数表单可编辑；生成草稿、校验、保存后需明确重启该下级。**仅升级管理端不会生效**。
- 缺省 0 不替使用人改变现场时序；这不是机组同步通信程序的周期整包刷新间隔。

操作入口和完整说明见[下级配置说明](../guides/lower-operations.md#控制命令最小发送间隔)。
