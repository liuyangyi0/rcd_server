## 修复

1. **历史命令编号不能因审计读取失败而重新入队。** 下级启动时读取同一 gateway 的有界历史编号摘要清单。历史读取失败不再当成“没有记录”；历史编号不能重放。清单可读时，真正的新编号仍按原有策略在审计降级下受理。历史清单本身不可读时，不接受无法证明是新编号的关联请求；旧入口不因审计故障停止控制。数据库和串口 worker 仍隔离，没有更改报文、ACK 或重试时序。
2. **原生任务准入前失败释放平台设备占用。** 模板/准入检查在原生任务行创建前产生带类型的错误。只有这类错误且任务编号为零时，操作记录为 `failed_before_execution` 并释放占用；派发结果不明仍保留 `unknown` 和原作业，不能自动重投。浏览器断开不取消这项限时持久化。工具快照刷新也识别该已结束状态。
3. **配置应用重启在维护内复核版本。** 管理端固化文件摘要，Agent 关闭下级修改准入、完成排空后，经真实下级 Operations 再核对摘要。冲突时不停止程序；确认解除自己持有的维护后记录冲突，解除不明确时仍保留未知状态。旧 Agent/下级不支持能力时拒绝无保护的配置应用重启。协议保持 schema v1，只追加能力和字段。
4. **半行日志不污染重传首条。** 每来源追加锁内先修复 JSONL 完整行边界。写入/同步失败回退到原完整边界，重传不会把第一条记录拼到半行上。已确认的完整行保留，ACK 仍在日志同步和原 SQLite 游标提交后返回。
