## 使用边界

同一来源/物理串口的上一条仍在执行时，下一条仍返回 `BadWaitingForResponse`，不自动排队或重发。调用方必须处理写响应；订阅 Send 的客户端必须接收坏质量终态，或读取新增 CommandResult 诊断节点。连续命令订阅建议队列至少 16；容量不足仍可溢出，历史明细以命令审计为准。

本次仅完成上述短时观察；一小时/过夜稳定性、真实设备连续动作回执及高负载队列容量尚未在本次验收中证明。客户端主动使用队列容量 1 或丢弃坏质量时，仍不能保证看到每个终态；不能把这次修复解释成任意频率、任意客户端配置下都不丢事件。
