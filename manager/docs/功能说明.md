# RCD OPC 管理程序功能说明

版本 `0.5.0-station-versions.1`。管理器连接多个 Rust 下级 OPC UA，将同一逻辑设备组的冗余来源合并后，对上提供统一 OPC UA、Web 和 REST。管理 OPC 固定使用 `4840`；Rust 下级默认使用 `4841`，同机多实例可分配其他端口。当前 Linux amd64 版已在 Kylin V10 SP1 隔离环境与真实串口设备联调；安全策略沿用受信任内网现状。

## 数据接入、分组和上级 OPC 树

- 下级发布“串口 → 设备/子站 → 原始点/计算点”拓扑；管理员把各冗余来源中的对应设备绑定到同一个逻辑组。同组同名点类型和值秩一致才合并，跨组重名、类型或方法签名冲突会隔离问题来源。
- 旧 `ns=2` 业务 NodeId、BrowseName、父子引用、读写权限和发送方法保持兼容。新管理信息只位于 `ns=3`。
- 上级 OPC 客户端可 Browse：`Groups/<group>/Members/<source>/Ports/<port>/Devices/<device>`。组级 `PointNodeCount` / `PointNodeIds` 可从 KKS 精确反查逻辑组；成员级 `CoverageKnown`、`ProvidedPointNodeIds` / `MissingPointNodeIds` 可确认这个 KKS 在可选 Source 中是否兼容可用。所有 String[] 均支持标准 OPC `IndexRange` 分页；点集/覆盖的单调 Revision 与内容指纹由同一个原子不可变快照提供，组级 `CatalogRevision` seqlock 又覆盖点表和全部成员，客户端前后校验同一个非零偶数即可排除热更新跨表混代。来源节点还显示连接/目录状态、是否可选、当前 Session 是否选中，以及期望/提供/缺失点数；设备节点显示站址、名称、KKS 前缀、原始/计算点数、有效归组、是否人工绑定和是否存在于已验证拓扑快照。
- 未发现的配置占位设备使用 `AddressKnown=false`，站址值返回 `BadWaitingForInitialData`，不会用合法的地址 0 冒充未知。缓存损坏只隔离对应来源；冲突来源不可选择，但仍保留已验证物理拓扑供排障。
- 物理树热更新按稳定 NodeId 差异化增删。来源改名、Endpoint 或统计变化会原位更新，已有订阅不会因整树删除重建而短暂收到节点不存在。

## Session 级整组选源和数据质量

客户端先浏览成员树，然后在同一 OPC Session 内把目标 `source_id` 写入 `Groups/<group>/SelectedSourceId`。一次写入切换该 Session 的整个逻辑组，不是单个 KKS、单个串口或所有客户端。若某个子站需要独立切换，应先把对应设备配置成独立逻辑组；成员物理树本身只读，不能形成无效的“来源/串口/站点”组合。

- 不同 Session 可为同组选择不同来源；`IsSelected` 的读和订阅也按 Session 隔离。Web 可以只修改指定在线 Session。
- 新 Session 复制默认源；修改默认源不影响已在线 Session。原 Session 断线重附着保留路由和订阅，Close/Timeout 后新 Session 回到默认。
- 不自动故障转移。选中离线来源仍保持路由，最后值改为 `BadNoCommunication`；等待首值、并集缺点和热删除分别返回规定坏质量。
- `Selectable=true` 表示允许选择，不等于覆盖全部并集点。应同时检查 `CompleteCoverage`；缺点来源被选中后，对应点返回 `BadConfigurationError`。

## 命令、下级采集和进程管理

- String 写入和 `SendCommand` 按发起瞬间的 Session 路由固定来源、物理串口和设备。相同来源+串口的命令不排队，pending 期间锁定相关组选源；ACK 成功、失败、丢包和超时进入命令审计。
- 下级采集运维按物理来源执行，不跟随上级 Session 选源。可开关串口、停启单站读取，显示期望状态、已应用状态、串口是否打开和实际通信；操作与同串口命令互斥，完成后自动恢复测试夹具状态。
- 每个物理站点可配置为未知、国产或俄供通信模块。未知和俄供不发送版本命令；国产在启动、重新启用或改为国产后查询一次，也可由 Web 手动刷新。通信模块/PLC 版本、原始载荷、实测类型、不一致和历史状态会持久化，并通过管理 Web、REST 和 `ns=3` 来源树同时提供；它不参与 KKS 合并或 Session 选源。
- 可读取和保存受限配置文件、查看分页日志。配置采用 revision/CAS、预检、备份和原子替换，保存后标记待重启，不把未保存草稿当成已应用配置。
- 同一 Linux 二进制可作为固定目标的进程 agent，支持 start/stop/restart、PID/运行时长/退出原因和有界进程输出。它只管理预绑定实例，不接受任意命令或任意路径；停止先 SIGTERM，超时才强制终止自有 child。
- 进程作业使用稳定 request_id、持久状态和来源级互斥。配置保存不自动重启；显式重启才应用磁盘配置。agent 离线仍需现场恢复，不属于 OPC 自动切源。

## Web、容量和本轮验收

Web 提供总览、组/来源配置、串口设备映射、在线 Session、手动整组选源、分页点位、设备版本、双源比较、命令/管理审计、告警、下级运维、配置和日志。下级日志可由独立 HTTP 线程批量推送并在管理端按来源集中滚动保存，断网使用有界磁盘 spool 补发且绝不阻塞串口；原下级文件读取继续作为完整日志兜底。上限为 20 个下级、10 个上级 Session；高频点值保留在内存，SQLite WAL 只保存配置、目录、站点版本缓存、日志 ACK 游标和审计，不保存日志正文。

本轮最终远端验证包括：Rust 352 项测试、严格 Clippy 和 release 构建；Web 152 项测试、桌面/移动视口和生产构建；Go 全模块测试、race、vet 和 release 构建；真实 Rust 下级旧点表兼容；管理 OPC Browse/Read/Subscribe；REST revision 冲突、SSE、审计和 SQLite 离线缓存。真实 `/dev/ttyWCH0` 国产站点返回通信模块 `V1.3`、PLC `V0.0`；启动和手动查询均成功，俄供/未知站点没有发出版本请求。最终管理器运行于 OPC `4840`、Web `8087`，Rust 下级运行于 `4841`。

尚需在正式投产容量下执行：20×约 5300 点满负载、10 个上级全量订阅、24 小时 soak、Linux systemd 正式安装和 Windows 服务验收。当前远端构建依赖目标系统的 glibc，适用于本次同环境部署。
