# RCD OPC 客户端接入与使用说明

适用版本：`0.4.4-opc-routing`

本文供使用 OPC UA 客户端接入 RCD 系统的人员阅读。

## 1. 需要连接哪个地址

OPC 客户端只连接 **RCD 管理程序**：

```text
opc.tcp://管理器IP:4840
```

需要查看 Web 页面时，浏览器打开：

```text
http://管理器IP:8080
```

不要连接 RCD 下级轮询程序的 `4841`、`4842` 等端口。

连接关系如下：

```text
OPC 客户端 ──4840──> RCD 管理程序

浏览器 ──8080──> RCD 管理程序

RCD 管理程序 ──4841/4842──> RCD 下级轮询程序
                              └─ 串口 → 设备/子站 → 变量
```

两个 RCD 程序的作用：

| 程序 | 作用 | OPC 客户端是否连接 |
|---|---|---|
| RCD 管理程序 `RcdManager` | 汇总所有下级数据，对 OPC 客户端提供统一变量 | 是，连接 `4840` |
| RCD 下级轮询程序 `rcd_server` | 轮询串口设备，把变量提供给管理程序 | 否 |

## 2. 连接 OPC 服务

在 OPC UA 客户端中新增连接：

```text
连接地址：opc.tcp://管理器IP:4840
```

第一次连接时，按现场要求信任 RCD 管理程序的 OPC UA 证书。

连接成功后，客户端可以浏览、读取和订阅业务变量。

如果连接失败，检查：

1. 管理器 IP 是否正确；
2. 端口是否为 `4840`；
3. 网络和防火墙是否允许访问 `4840`；
4. 客户端是否已信任管理程序证书。

## 3. 查找、读取和订阅变量

OPC 客户端需要识别两个命名空间：

| 命名空间 URI | 用途 | 本版本常见编号 |
|---|---|---|
| `urn:SerialServer` | 业务变量，用于读取和订阅 | `ns=2` |
| `urn:RcdManager:management` | 逻辑组、来源状态和选源节点 | `ns=3` |

业务变量可以从下面的路径浏览：

```text
Objects
└─ Devices
   └─ 业务变量
```

业务变量示例：

```text
ns=2;s=UNIT1_TEMP
```

客户端可以对变量执行：

- 读取；
- 定时读取；
- 建立订阅；
- 查看变量值、时间戳和数据质量。

正式接入时，应读取 `Server/NamespaceArray`，分别按两个 URI 查找实际命名空间编号，不要永久写死 `ns=2` 或 `ns=3`。

## 4. 理解变量来源

每个 RCD 下级轮询程序内部的结构为：

```text
下级来源
└─ 串口
   └─ 设备/子站
      └─ 变量
```

两套互为备用的设备会在 RCD 管理程序中绑定到同一个逻辑组。例如：

| 来源 | 实际设备 | 逻辑组 |
|---|---|---|
| `lower-a` | `/dev/ttyS0 → 设备1` | `device-a` |
| `lower-b` | `/dev/ttyUSB0 → 设备7` | `device-a` |

逻辑组表示这两套设备提供同一批业务变量。

切换来源时，切换的是当前 OPC 会话中的整个逻辑组，不是单个变量，也不是整个下级程序。

不同 OPC 会话可以为同一个逻辑组选择不同来源，互不影响。

## 5. 在 OPC 客户端中切换来源

### 5.1 找到变量所属的逻辑组

推荐先在 Web 的“点位浏览”中按变量名称查询所属逻辑组。

如果只使用 OPC 客户端，可以浏览：

```text
Objects
└─ RcdManager
   └─ Groups
      └─ 逻辑组
         ├─ PointNodeIds
         ├─ SelectedSourceId
         ├─ SelectionRevision
         ├─ PendingCommandCount
         └─ Members
```

`PointNodeIds` 是该逻辑组包含的业务变量 identifier 清单。例如完整 NodeId 为 `ns=2;s=UNIT1_TEMP` 时，数组中保存的是 `UNIT1_TEMP`。

在各逻辑组的 `PointNodeIds` 中找到目标变量 identifier，即可确定变量所属的逻辑组。如果客户端不能一次显示完整数组，应使用 OPC `IndexRange` 分页读取。

### 5.2 查看可以选择的来源

展开目标逻辑组的 `Members`：

```text
Members
└─ 来源
   ├─ Selectable
   ├─ IsSelected
   ├─ ConnectionState
   ├─ CompleteCoverage
   └─ Ports
      └─ 串口
         └─ Devices
            └─ 设备
```

选择来源前检查：

| 节点 | 要求 |
|---|---|
| `Selectable` | 必须为 `true` |
| `ConnectionState` | 建议为 `Connected` |
| `CompleteCoverage` | 建议为 `true` |
| `PendingCommandCount` | 必须为 `0` |

通过 `Ports → Devices` 可以确认该来源对应的实际串口和设备。

### 5.3 执行切换

1. 记录当前的 `SelectedSourceId` 和 `SelectionRevision`。
2. 向 `SelectedSourceId` 写入 **String** 类型的来源编号，例如：

```text
lower-b
```

3. 写入成功后重新读取并确认：

| 检查项 | 正确结果 |
|---|---|
| OPC 写入结果 | `Good` |
| `SelectedSourceId` | 等于目标来源编号 |
| `SelectionRevision` | 比切换前增加 |
| `Members/lower-b/IsSelected` | `true` |

`SelectedSourceId` 只能写来源编号。不要写串口名、设备名、显示名称或连接地址。

### 5.4 必须使用同一个 OPC 会话

写入 `SelectedSourceId` 的 OPC 会话，必须与读取或订阅业务变量的 OPC 会话相同。

```text
同一个 OPC 会话
  ├─ 写 SelectedSourceId
  └─ 读取或订阅业务变量
```

如果客户端使用一个会话写入、另一个会话订阅，写入虽然可能成功，但订阅数据不会切换。

## 6. Web 页面怎么使用

浏览器打开：

```text
http://管理器IP:8080
```

OPC 客户端使用人员主要查看以下页面：

| Web 页面 | 用途 |
|---|---|
| 运行总览 | 查看管理程序、下级来源、点位质量和告警状态 |
| 分组与选源 | 选择在线会话，查看逻辑组，并为该会话切换来源 |
| 下级 OPC | 查看下级连接；通过来源操作中的“串口 / 设备映射”查看物理设备关系 |
| 点位浏览 | 查看变量、数据质量、所属逻辑组和来源 |
| 命令记录 | 查看命令执行记录 |
| 告警与审计 | 查看告警和管理操作记录 |

### 6.1 在 Web 中为当前 OPC 会话切换来源

1. 先让 OPC 客户端连接管理程序的 `4840`。
2. 打开 Web 的“**分组与选源**”页面。
3. 在“**当前查看会话**”中选择该 OPC 客户端对应的在线会话。可根据客户端名称、会话编号和远端地址进行确认。
4. 在逻辑组列表中找到需要切换的逻辑组。
5. 点击该组的“**切源**”，或者打开组详情后点击“**切换当前 Session 的整组来源**”。
6. 选择目标来源，确认已核对目标下级状态，然后点击“**确认切换**”。
7. 确认页面显示的当前选中源已经改变。
8. 回到 OPC 客户端，检查订阅变量和值的数据质量。

Web 中切换的是选中的在线会话，不会影响其他 OPC 客户端会话。

“默认来源”只影响以后新建的 OPC 会话，不会切换已经在线的会话。

## 7. 数据质量和常见问题

| 状态或问题 | 含义或处理方法 |
|---|---|
| `Good` | 数据正常 |
| `BadNoCommunication` | 当前来源离线或通信中断 |
| `BadOutOfService` | 变量已停用或当前不可服务 |
| `BadConfigurationError` | 来源、设备分组或变量覆盖不符合要求 |
| `BadWaitingForResponse` | 有命令等待设备响应，暂时不能切换来源 |
| OPC 客户端连不上 | 确认连接管理程序的 `4840` |
| 找不到目标变量 | 检查业务命名空间和变量名称 |
| 写入成功但数据未切换 | 检查写入和订阅是否使用同一个 OPC 会话 |
| 目标来源不能选择 | 检查 `Selectable`、连接状态和命令等待状态 |

系统不会自动切换离线来源。当前来源离线时，需要通过 OPC 客户端或 Web 手工选择其他来源。

## 8. 使用前检查

- [ ] OPC 客户端连接的是管理程序 `4840`；
- [ ] 客户端已信任管理程序证书；
- [ ] 能够找到并订阅业务变量；
- [ ] 已确认变量所属的逻辑组；
- [ ] 已确认候选来源对应的实际串口和设备；
- [ ] 写入选源和读取变量使用同一个 OPC 会话；
- [ ] 切换后已检查 `SelectionRevision`、`IsSelected` 和数据质量。
