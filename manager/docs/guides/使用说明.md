# RCD OPC 客户端接入、选源与中央计算使用说明

本文按当前RCD管理接口说明。带revision的`SelectSource` Method已于2026-10-21随`0.6.12-state-names.20261021.1`部署到30、58、46，旧String写入接口保留；其他旧服务须先确认是否支持。见[发布及验收记录](../validation/state-input-digit-names-20261021.md)。

管理网页要求账号密码登录，使用管理员提供的当前账号，右上角可修改密码或退出。OPC 客户端不需要网页登录；详细操作见 [网页登录与操作优化](web-login-and-usability.md)。全部软件的分工与现场入口见[整体软件使用说明](../../../docs/整体软件使用说明.md)。

本文供使用 OPC UA 客户端接入 RCD 系统的人员阅读。

## 1. 需要连接哪个地址

OPC 客户端只连接 **RCD 管理程序**：

```text
opc.tcp://管理器IP:4840
```

需要查看 Web 页面时，浏览器打开：

```text
http://管理器IP:8087
```

正常业务接入不要绕过管理端直连原采集程序`4841`或新通信程序`4842`；维护诊断另行确认目标。

连接关系如下：

```text
OPC 客户端 ──4840──> RCD 管理程序

浏览器 ──8087──> RCD 管理程序

RCD 管理程序 ──4841──> 原采集程序 ──> 串口设备/子站
             └─4842──> 新通信程序（当前仅46）──> 对方机组
```

数据通道中的程序作用：

| 程序 | 作用 | OPC 客户端是否连接 |
|---|---|---|
| RCD 管理程序 `RcdManager` | 汇总所有下级数据，对 OPC 客户端提供统一变量 | 是，连接 `4840` |
| RCD 下级轮询程序 `rcd_server` | 轮询串口设备，把变量提供给管理程序 | 否 |
| 新通信程序 `rcd_communicate` | 机组数据快照收发，接收原名变量、接受发送输入 | 正常通过46管理端；[独立说明](../../../communicate/docs/opc-client-guide.md) |

## 2. 连接 OPC 服务

在 OPC UA 客户端中新增连接：

```text
连接地址：opc.tcp://管理器IP:4840
```

第一次连接时，按现场要求信任 RCD 管理程序的 OPC UA 证书。

连接成功后，客户端可以浏览、读取和订阅业务变量。

如果连接失败，检查：

1. 管理器 IP 是否正确；
2. 端口是否为 `4840`；
3. 网络和防火墙是否允许访问 `4840`；
4. 客户端是否已信任管理程序证书。

## 3. 查找、读取和订阅变量

连接成功后，从下面的路径浏览业务变量：

```text
Objects
└─ Devices
   └─ 业务变量
```

客户端可以对变量执行：

- 读取；
- 定时读取；
- 建立订阅；
- 查看变量值、时间戳和数据质量。

## 4. 理解逻辑组和来源

管理员已经在 RCD 管理程序中配置好业务变量所属的逻辑组。OPC 客户端切源时只使用逻辑组编号和来源编号。

例如，逻辑组 `device-a` 有两个候选来源：

| 逻辑组 | 候选来源 |
|---|---|
| `device-a` | `lower-a`、`lower-b` |

逻辑组表示两个来源可以提供同一批业务变量。

切换来源时，切换的是当前 OPC 会话中的整个逻辑组，不是单个变量，也不是整个下级程序。

不同 OPC 会话可以为同一个逻辑组选择不同来源，互不影响。

## 5. 在 OPC 客户端中切换来源

### 5.1 找到变量所属的逻辑组

在 OPC 客户端中浏览：

```text
Objects
└─ RcdManager
   └─ Groups
      └─ 逻辑组
         ├─ PointNodeIds
         ├─ MemberSourceIds
         ├─ SelectedSourceId
         ├─ SelectionRevision
         ├─ PendingCommandCount
         └─ Members
```

`PointNodeIds` 是该逻辑组包含的业务变量名称清单，例如 `UNIT1_TEMP`。

在各逻辑组的 `PointNodeIds` 中找到目标变量标识符，即可确定变量所属的逻辑组。如果客户端不能一次显示完整数组，应使用 OPC `IndexRange` 分页读取。

### 5.2 查看成员及可选状态

先读取目标逻辑组的 `MemberSourceIds`，得到已配置成员编号。列表包含离线、停用、目录冲突或尚不可选的来源，不能直接当作在线健康列表。

再展开目标逻辑组的 `Members`：

```text
Members
└─ 来源
   ├─ Selectable
   ├─ IsSelected
   ├─ ConnectionState
   └─ CompleteCoverage
```

选择来源前检查：

| 节点 | 要求 |
|---|---|
| `Selectable` | 必须为 `true` |
| `ConnectionState` | 建议为 `Connected` |
| `CompleteCoverage` | 建议为 `true` |
| `PendingCommandCount` | 必须为 `0` |

### 5.3 推荐：带revision校验的Method

1. 在当前业务OPC Session中读取本组`SelectionRevision`。
2. 在本组对象调用`SelectSource`，传入目标`SourceId`（String）和刚读取的`ExpectedRevision`（UInt64）。

```text
ObjectId：ns=3;s=Groups/device-a
MethodId：ns=3;s=Groups/device-a/SelectSource
输入：String lower-b、UInt64 10（10仅为示例，实际使用读到的版本）
成功输出：String lower-b、UInt64 11
```

3. 检查该CallMethodResult.StatusCode为Good，再使用输出的来源与版本确认本次提交。返回后其他合法操作仍可能改变它。
4. 若返回BadInvalidState，表示期望版本冲突；重新读状态并确认选择意图，不能悄悄套用新版本重试。BadWaitingForResponse表示本组存在在途事务，失败不会修改路由。

来源必须属于该组并可选，但离线缓存来源也可能允许选择。选择成功不保证业务点为Good，已有订阅按目标Session异步刷新。手动Method与下面的旧Write均会将本Session本组改为手动固定，不再跟随自动选源。

### 5.4 兼容：写入SelectedSourceId

此方式供不能调用Method的旧客户端使用，不携带客户端期望revision。以下读回只用于确认，不能防止旧操作覆盖Web或其他新选择。

1. 记录当前的 `SelectedSourceId` 和 `SelectionRevision`。
2. 向 `SelectedSourceId` 写入 **String** 类型的来源编号，例如：

```text
lower-b
```

3. 写入成功后重新读取并确认：

| 检查项 | 正确结果 |
|---|---|
| OPC 写入结果 | `Good` |
| `SelectedSourceId` | 等于目标来源编号 |
| `SelectionRevision` | 比切换前增加 |
| `Members/lower-b/IsSelected` | `true` |

`SelectedSourceId` 只能写来源编号。

### 5.5 必须使用同一个 OPC 会话

调用SelectSource或写入SelectedSourceId的OPC会话，必须与读取、订阅或后续写入业务变量的OPC会话相同。

```text
同一个 OPC 会话
  ├─ 调用SelectSource（或旧接口写SelectedSourceId）
  └─ 读取或订阅业务变量
```

如果客户端使用一个会话写入、另一个会话订阅，写入虽然可能成功，但订阅数据不会切换。

`SelectionRevision`只用于选源，不是新通信程序`TransmitStatus`中的发送快照revision。选源不撤销旧下级已经接受的数据，也不等于停止旧串口发送；新通信接口的完整字段、刷新和整包规则见[通信OPC客户端说明](../../../communicate/docs/opc-client-guide.md)。

## 6. Web 页面怎么使用（可选）

浏览器打开：

```text
http://管理器IP:8087
```

能够调用SelectSource或写入SelectedSourceId的OPC客户端，不需要使用Web完成切源。Web还负责配置、计算、日志与运维；就客户端选源而言，操作人员可用它修改指定在线会话。

OPC 客户端使用人员可以查看以下页面：

| Web 页面 | 用途 |
|---|---|
| 运行总览 | 查看管理程序、下级来源、点位质量和告警状态 |
| 分组与选源 | 选择在线会话，查看逻辑组，并为该会话切换来源 |
| 下级 OPC | 查看各下级来源的连接状态 |
| 点位浏览 | 查看变量、数据质量、所属逻辑组和来源 |
| 计算中心 | 查看中央计算结果，导入、校验、激活或回滚 `calc.toml`，切换下级计算模式 |
| 命令记录 | 查看命令执行记录 |
| 告警与审计 | 查看告警和管理操作记录 |

### 6.1 通过 Web 代替 OPC 客户端切源

1. 先让 OPC 客户端连接管理程序的 `4840`。
2. 打开 Web 的“**分组与选源**”页面。
3. 在“**当前查看会话**”中选择该 OPC 客户端对应的在线会话。可根据客户端名称、会话编号和远端地址进行确认。
4. 在逻辑组列表中找到需要切换的逻辑组。
5. 点击该组的“**切源**”，或者打开组详情后点击“**切换当前 Session 的整组来源**”。
6. 选择目标来源，确认已核对目标下级状态，然后点击“**确认切换**”。
7. 确认页面显示的当前选中源已经改变。
8. 回到 OPC 客户端，检查订阅变量和值的数据质量。

Web 中切换的是选中的在线会话，不会影响其他 OPC 客户端会话。

修改“默认来源”不改变已经在线Session的原始点路由，新Session用当时默认源初始化；但中央计算会按新默认来源重新取数，所有Session共享的计算结果可能改变。

### 6.2 OPC 客户端下发命令并判断结果

客户端可使用旧兼容方法或明确逻辑组的方法。以下是完整NodeId，不是浏览路径：

| 入口 | ObjectId | MethodId |
| --- | --- | --- |
| 旧串口方法 | `ns=2;s=Methods` | `ns=2;s=<port>_SendCommand` |
| 逻辑组方法 | `ns=3;s=Groups/<group_id>` | `ns=3;s=Groups/<group_id>/SendCommand` |

两者输入均为`HexData String`（不含校验和的十六进制文本），成功输出`Result String`；管理端按本次Session选源固定下级、物理串口和设备。先Browse确认实际节点，不将`Objects/Methods`拼入字符串identifier。

Method 调用现在等待真实设备 ACK，不能只根据“请求已发出”判断成功：

| Method 结果 | 含义 |
|---|---|
| `Good`，Result=`"1"` | 收到协议ACK；不表示设备动作反馈已核实 |
| `BadOutOfService` | 串口被停用、尚未应用或当前不可服务 |
| `BadNoCommunication` | 管理程序与所选下级 OPC 不通 |
| `BadUnexpectedError` | 其他执行失败，或旧协议仅返回`3`、无法进一步区分原因；同时查错误明细 |
| `BadTimeout` | 跟踪协议明确ACK超时/期限到期，或管理端在期限内未得到终态 |
| `BadWaitingForResponse` | 同一来源和物理串口有执行或排队命令；同步Method不入队 |

客户端还应订阅同一Session的`ns=2;s=<port>_Send`或`ns=3;s=Groups/<group_id>/Send`，用于显示最近命令的执行过程：

- `2 / Good`：已接受、尚未终止，可能在管理端排队或等待设备ACK；
- `1 / Good`：收到协议ACK；
- `3 / Bad...`：执行失败，具体原因看该 DataValue 的 StatusCode；
- `PendingCommandCount`回到`0`：本组排队与执行事务均已释放，不是某一条命令的成功标志。区分排队/执行看`QueuedCommandCount`、`ExecutingCommandCount`及命令记录state，逐条终态按command_id核对。

也可以写`ns=2;s=<port>_Send`或`ns=3;s=Groups/<group_id>/Send`。同一管理端按固定来源＋物理串口FIFO受理，容量64条（含执行中）；Write返回Good只表示管理端接受，可能尚未派发给下级。队满返回BadWaitingForResponse，不覆盖已接收项。相同载荷不合并，总期限包含排队时间。

结果节点是最近命令状态，不是每条已入队请求的完整结果日志。连续下发时应在“命令记录 → 执行过程”按command_id逐条核对；订阅可能丢失中间变化，不能用最后一次`1/3`替所有请求确认。旧协议的ACK没有命令编号，更不能据时间或同报文猜关联。结果不明不换源、不盲目重投，详见[命令追踪](command-tracking.md)。

命令失败不会把业务采集KKS改成命令内容；串口或下级通信中断时原始采集点按类型清零并标记BadNoCommunication。

## 7. 中央计算点怎么使用

中央计算启用后，计算点仍位于旧业务路径 `Objects/Devices/<KKS>`，并继续使用原来的 `ns=2;s=<KKS>` NodeId、BrowseName、数据类型和只读权限。上级 OPC 客户端不需要修改点表。

中央计算与普通原始点的选源规则不同：

原始采集点为BadNoCommunication时，管理端先按类型归零，再执行表达式；只有实际使用该输入的执行路径才传播通信坏质量，IF未执行分支不污染结果。计算点保留最终公式值，不强制清零，客户端必须同时判断值和StatusCode。独立常量及无关来源不受该次断线影响；[状态输入](calculation-state-inputs.md)可固定来源，离线数值5仍可为Good，不能与普通采集点混为一谈。

| 点位类型 | 取数路由 |
|---|---|
| 原始采集点 | 按当前 OPC Session 的 `SelectedSourceId` |
| 管理端计算点 | 始终按每个逻辑组的 `DefaultSourceId` |

因此，同一逻辑组中两个 OPC Session 可以看到不同的原始点，但看到的计算结果完全相同。修改某个 Session 的 `SelectedSourceId` 不会触发或改变中央计算；只有修改组默认来源、下级连接状态、目录或原始输入时才会重算。

OPC 客户端可从以下只读路径查看计算中心状态：

```text
Objects
└─ RcdManager
   └─ Calculations
      ├─ RoutingMode                 # 固定为 DefaultSources
      ├─ ActiveRevision
      ├─ ConfigHash
      ├─ RuleCount
      ├─ GoodCount / BadCount
      ├─ DefaultRouteRevision
      ├─ LastEvaluationAt
      ├─ LastEvaluationDurationMs
      ├─ PendingRestart
      └─ CalculationNodeIds
```

`CalculationNodeIds` 是全部中央计算点的 NodeId 数组，支持 OPC `IndexRange` 分页读取。规则只能在 Web“计算中心”修改，OPC 侧不能写规则或激活版本。

### 7.1 在 Web 导入和激活规则

1. 打开“计算中心 → 规则配置”。
2. 从本地选择 `calc.toml`，或选择一个在线下级并点击“读取下级”。
3. 保存为草稿；保存草稿不会改变当前运行版本。
4. 点击“校验当前内容”。重复输出、循环依赖、缺点、重名、类型和表达式错误必须全部修复。
5. 校验通过后点击“激活中央版本”。普通表达式修改会热激活；已发布点的数据类型改变会显示“待重启”，当前版本继续运行。
6. 在“实时结果”检查 KKS、值、质量、求值时间和默认路由版本；需要时导出 CSV。

历史版本在“版本历史”中不可改写。执行回滚会复制旧内容并生成一个新 revision，不会删除原历史。

### 7.2 把下级切换为 manager 模式

迁移顺序必须是：先确认中央配置已激活且结果正常，再到“计算中心 → 下级模式”把下级设为 `manager`，最后到下级运维页明确执行重启。保存模式不会自动重启。

`manager` 模式下，下级不加载、不执行、也不发布本地计算点；本机 `calc.toml` 仍保留为只读回滚副本。恢复时顺序相反：先把下级设回 `local` 并重启，确认下级计算点恢复后，才允许停用中央计算。

## 8. 数据质量和常见问题

### 8.1 查看下级日志和调整日志等级

进入 Web 左侧“下级日志”，先选择来源。页面默认显示该来源最新集中日志，可按等级、串口、站点和关键字过滤；如果页面因上次保留的筛选而看不到记录，点击“显示最新日志”即可一次清除全部筛选。

页面“下级日志等级”同时显示“当前运行”和“已保存配置”。日常使用建议保持 `INFO`；短时排障可切到 `DEBUG` 或 `TRACE`，完成后应恢复 `INFO`，否则会快速增加下级文件和集中日志量。保存新等级后若显示“需要重启”，到“下级 OPC → 运维 → 进程”明确重启该来源；保存动作本身不会重启或中断串口采集。若显示 `RUST_LOG` 环境变量覆盖，需要修改进程启动环境后再重启。

集中页仍无记录时，到“下级 OPC → 运维 → 日志”读取下级本机滚动文件，并检查页面中的“HTTP 推送”状态和 `source_id` 是否与管理器来源 ID 一致。本机日志始终是兜底，不依赖管理端网络。

| 状态或问题 | 含义或处理方法 |
|---|---|
| `Good` | 数据正常 |
| `BadNoCommunication` | 当前来源离线或通信中断 |
| `BadOutOfService` | 变量已停用或当前不可服务 |
| `BadConfigurationError` | 来源、设备分组或变量覆盖不符合要求 |
| `BadWaitingForResponse` | 有命令等待设备响应，暂时不能切换来源 |
| Method 返回 `Good` 且 Result=`"1"` | 真实设备 ACK 成功，不只是下级入队成功 |
| `_Send=3` | 命令失败；必须同时查看 StatusCode 区分不可服务、通信失败和超时 |
| 计算点 `BadWaitingForInitialData` | 默认来源的实际执行路径尚无首值 |
| 计算点 `BadConfigurationError` | 未配置默认源、缺少依赖，或表达式运行错误；运行错误使用规则默认值 |
| OPC 客户端连不上 | 确认连接管理程序的 `4840` |
| 找不到目标变量 | 检查业务命名空间和变量名称 |
| 写入成功但数据未切换 | 检查写入和订阅是否使用同一个 OPC 会话 |
| 目标来源不能选择 | 检查 `Selectable`、连接状态和命令等待状态 |

自动切源默认关闭。只有开启组策略且本Session本组参与“跟随自动”，才会在故障确认、备用健康确认及冷却条件满足后切换；没有健康备用时保持原选择，不自动回切。手动选源会退出本组自动参与。默认源是否自动切换另有开关，见[自动切源与差异告警](redundancy.md)。

## 9. 使用前检查

### 如何读取各来源站点的好坏

在管理端 OPC 的 `ns=3` 浏览：

`Groups/<组ID>/Members/<来源ID>/Ports/<串口>/Devices/<站点>/CommunicationState`

该节点本身就是可读取、可订阅的 **UInt32 数值变量**：`0=未知/过期`、`1=正常`、
`2=通信异常`、`3=串口未打开`、`4=串口或站点停用`、`5=下级 OPC 离线`。
例如值为 `2`、节点质量为 `Good`，表示“管理器确认该站点通信异常”，不是通信正常。
`CommunicationStateText` 给出中文说明，`CommunicationObservedAt` 给出状态接收时间。
业务点自己的质量仍然按原规则处理。

这些节点按物理来源独立，不随选源切换；可以同时订阅同一组的三个来源，比较站点状态后再选源。
约每 2 秒刷新，超过 15 秒没有新状态则显示未知，不沿用旧正常状态。
串口路径有转义，请使用 Browse 取得完整 NodeId。
详细状态定义见 [站点通信状态说明](device-groups.md#站点通信状态数值变量)。

### 检查清单

- [ ] OPC 客户端连接的是管理程序 `4840`；
- [ ] 客户端已信任管理程序证书；
- [ ] 能够找到并订阅业务变量；
- [ ] 已确认变量所属的逻辑组；
- [ ] 已读取该逻辑组的候选来源；
- [ ] 命令客户端会检查 Method StatusCode，或订阅 `_Send` 的值和 StatusCode；
- [ ] 写入选源和读取变量使用同一个 OPC 会话；
- [ ] 切换后已检查 `SelectionRevision`、`IsSelected` 和数据质量。
- [ ] 已理解中央计算点使用组默认来源，不跟随 Session 独立选源；
- [ ] 切换下级计算模式前，已按规定完成中央激活或本地恢复并再次明确重启。
