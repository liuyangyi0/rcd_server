# 运维平台：主机、软件种类和首次安装

本文对应 `v2.19.16-rcd.9`；部署与验收状态见[上线记录](../validation/semaphore-rcd9-deployment-20261022.md)，不以源码版本判断。

## 入口与分工

运维平台：`http://192.168.10.46:3000`。沿用现有账号和权限。

- **设备与版本**：主机资源、实际运行版本、检查连接、组件操作；“接入与首装记录”可找回原作业。
- **软件包**：登记软件种类，上传与下载标准发布包，选择目标机器。
- **操作任务**：升级、恢复和服务控制结果。主机接入向导显示自己的原生任务入口。
- **高级管理**：维护原生 SSH / sudo 凭据、仓库等。日常发布不填写剧本和服务器路径。

OPC 采集、串口、站点、业务配置和日志仍在对应的 OPC 管理网页。运维连接正常不代表物理设备通信正常。

## 软件种类与软件版本不是一回事

内置种类为下级 OPC、OPC 管理端、RCD Agent、串口通信程序。上传它们的新版本不需要新增种类。

其他程序先在“软件包 → 添加软件种类”登记稳定标识、显示名称和固定启动参数，再上传该种类的版本包。首版接受 Linux 单 ELF 二进制，不支持任意安装脚本、容器、Windows 或多文件安装器。

新种类的标识为小写字母开头、最多32位的字母/数字/短横线，例如 `report-worker`。登记后运行定义不可改写；软件包不能变更安装路径、服务账户或启动参数。最多登记32种自定义软件。

自定义软件必须支持正常 `SIGTERM` 退出。这里的停止是进程级停止，不是 OPC 管理端的设备控制事务排空。

固定路径示例：

```text
程序：/opt/rcd/apps/report-worker/bin/report-worker
工作目录：/var/lib/rcd/apps/report-worker
用户服务：rcd-app-report-worker.service
```

## 上传新版本

1. 由构建人员生成单组件 `*.rcd.tar.gz` 标准包，包含二进制和公开版本清单。
2. 在“软件包 → 上传软件包”选择文件，页面立即显示文件名/大小；仅接受不超过256 MiB的`.rcd.tar.gz`。扩展名通过不等于内容通过，仍须服务端校验。上传不会执行程序或触发安装。
3. 检查组件、版本、平台、说明和校验结果；通过后再选择目标。

普通文件或任意压缩包不能代替发布包。同一发布编号不能被不同内容覆盖。第三方程序不要求提供 RCD 的 `version --json`，其版本由公开清单与实际进程映像 SHA-256 对应确认。

构建人员的打包命令及清单示例见[发布工具](../../../tools/release/README.md#额外软件的标准包)和[包格式](../../../contracts/release-package/README.md)。软件使用人员只需在网页选择生成的包，不手填摘要、安装目录或命令。

## 添加空白主机

前提：Linux、Python3、systemd、可登录的 SSH，以及已存在的非 root 服务账户。首次写入系统安装目录需要明确的 sudo/root权限；平台不偷偷创建账户、关闭主机指纹检查或放宽 KYSEC。

1. 在高级管理保存原生加密 SSH 凭据；需要提权时保存对应 sudo 凭据。
2. “设备与版本 → 添加主机”：填写名称、固定IP、SSH端口、登录账户、服务账户，从下拉框选择凭据。
3. 运行公共主机密钥扫描；从目标机器或可信管理员处核对显示的完整 SHA-256 指纹后确认。仅扫描不能证明身份，不能看到指纹就盲目确认。
4. 平台通过原生任务检查 SSH、系统、账户和架构。已有主机密钥改变时停止接入，不覆盖原信任记录。
5. 检查成功后登记主机；此时不代表安装了软件。选择兼容包，明确执行首次安装。

首次安装拒绝覆盖已有程序、服务、应用归属或数据。安装后保持停止，显示“已安装、待配置”；不创建串口业务配置，不开启真实串口。内置 RCD 程序首次落盘不等于完整业务接入，仍需其业务配置和维护绑定。自定义软件生成固定用户服务及归属记录，完成配置后再明确启动。

## 已有主机安装一种新软件

先执行“检查状态”。组件明确显示未安装后，从设备详情选择“首次安装”，一次选择一台主机和一个兼容包。不能用“普通升级”冒充首次安装，也不能把“无法确认”当成“没有安装”。

原有软件的新版本使用“升级”；历史恢复只选择已经证明可恢复的成功版本。二者都不覆盖使用人的业务配置、数据库和PKI。

## CPU、内存、磁盘和网络怎么看

设备列表显示资源摘要；详情显示 CPU 利用率、逻辑核数、内存总量/可用量、磁盘容量、网卡地址、链路、累计流量及短采样窗口速率。

- 每分钟巡检一次，不是实时监控。刷新页面只读取已有快照；“检查状态”才创建新的只读任务。
- 超过180秒或检查失败时显示历史快照及观测时间。单项指标失败显示未知，不填0。
- 本轮指标失败可保留上次成功值，但会同时标明最后成功时间和最后尝试时间。
- 网卡 `up` 不证明业务网络、OPC 或物理站点可达；流量计数回绕、网卡变化或时间异常时速率显示未知。
- 网卡地址保留掩码，例如 `192.168.10.46/24`；它是接口地址与网络前缀长度，不是无效IP。

## 失败或回复丢失

“设备与版本 → 接入与首装记录”可按主机、作业编号或状态查找服务端原记录。换浏览器或清除本地缓存后，也从这里“查看原作业”，无需重新添加主机。列表显示总数/页数；读取失败保留上次确认页面，不把失败当成记录已删除。

关闭向导不取消已进入队列的操作。回复丢失时使用“刷新原作业/查看原任务”，不要换编号重新点击安装。未知结果保留占用，不自动重投、强杀或删除事务文件。

原安装任务已结束但结果未知时，页面可提供“补查原首装结果”，需勾选“确认仅核对原首装记录，不重新安装、不启停”。补查通过原生队列读取原目标的安装回执和当前身份，不重新传包、安装或启停；安装任务和补查任务有独立日志。证据一致后可确认“已安装、保持停止”；证据缺失、损坏或身份变化仍保持未知，不解除占用。原安装任务的失败结论不会被改成成功。

首次落盘但未启动的软件不是可恢复版本。完成同一设备、组件和程序摘要的明确成功启动验收后，才出现对应恢复点；历史中的时间标明为启动验收时间，不冒充安装时间。

同一主机的首次安装、升级和启停互斥。串口通信程序尚无设备事务排空能力，运行状态下不提供假安全的升级/停止；明确停止后才可发布，不能借用采集程序的 Agent 来停止它。
