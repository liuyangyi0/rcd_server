# 采集点表 CSV 填写与校验规则

适用于 Rust 采集程序的 `rcd*.csv`，不适用于机组通信程序的 `points.csv`。

软件负责校验和报错，**不推测设备协议、不自动修改长度、点地址或删除变量**。配置编写人员应依据对应设备的协议维护点表。

## 文件结构

使用 UTF-8，可带文件开头的 BOM；支持 LF/CRLF 换行。每行保持 9 列，配置行不足的列用逗号补空。一个文件描述同一串口上的一个站点。

前 7 行顺序固定，第 2 列填写值：

| 行 | 标准字段 | 兼容旧标签 | 值的规则 |
| --- | --- | --- | --- |
| 1 | `com` | `COM` | 非空串口名，例如 `/dev/ttyWCH0` |
| 2 | `baud_rate` | `BaudRate` | 大于 0 的 UInt32 整数，须符合实际串口设置 |
| 3 | `is_special` | `IsSpecial` | 使用小写 `true` / `false`；兼容已有的 `FALSE` |
| 4 | `com_index` | `ComIndex` | 0–255 的整数 |
| 5 | `device_id` | `DeviceID` | 0–255 的整数，须符合实际设备地址 |
| 6 | `data_len` | `DataLen` | 0–255 的整数，按该设备协议填写轮询长度 |
| 7 | `kks_prefix` | `Pre` / `KKSPrefix` | 拼接到每个点名前，可为空；不得包含控制字符 |

字段标签兼容大小写、下划线和两侧空白差异，但不允许未知字段或交换行顺序。兼容的是标签，不会将点名、点值类型等内容自动改大小写。不要填写大写 `TRUE`：旧启动解析器不会将它识别为真，新保存校验也不会擅自把它变成特殊串口模式。

第 8 行必须是列头，不要额外插入“分隔行”：

```csv
kks,type_,f_type,byte_index,bit_index,def,max,min,lh
```

旧列头 `KKS,Type,F_Type,byte_index,bit_index,Def,Max,Min,LH` 同样支持，列数和顺序必须一致。第 9 行起每行一个点：

| 列 | 规则 |
| --- | --- |
| `kks` | 点名非空、无控制字符；加上前缀后，在同一下级完整配置集中不能重复 |
| `type_` | 仅小写 `uint`、`bool`、`float` |
| `f_type` | 预留功能标识，不能省掉这一列 |
| `byte_index` | 从 **1** 开始，指向响应的状态数据区，不包含地址、命令、长度和校验字节 |
| `bit_index` | 单个位 `0`–`7`，或闭区间，如 `0.15`；起点不得大于终点，宽度最多 32 位 |
| `def` / `max` / `min` | UInt32 整数；预留字段也必须提供有效数值，通常填写 `0` |
| `lh` | `0` 小端，`1` 大端，不能填其它值 |

## 长度与越界

- `DataLen` 会直接进入轮询请求，不只是供网页检查的数字，不能为了通过校验随意增大。
- 响应协议的状态区有 `Len + 1` 字节。接收器兼容已有点表中两种长度约定：协议 `Len`，或实际状态区字节数。应沿用对应设备的协议约定，不自行混用。
- 静态校验为兼容这两种约定，以 `DataLen + 1` 为可支持的状态区上界；超出此上界一定不合法。静态通过不证明设备一定返回足够的数据。
- 跨字节位段必须检查末尾。例如 `byte_index=20, bit_index=0.15` 使用第 20、21 字节，至少需要 21 字节状态数据，不能只检查起始字节 20。

程序不会依据点名中的 `AI` 编号、文件名或最高地址自动填写 `DataLen`。串口和站点以文件头为准，也不从文件名推断。

## 保存规则与错误处理

新版网页按“修改 → 校验当前草稿 → 保存到下级”操作；校验自动合并参数表单，不再单独点击“生成草稿”。校验不写文件，保存前仍会重新检查完整配置集。

按本轮确认的规则，点的字节地址、位号及位范围错误作为**非阻断提示**：保留具体文件、行号、点名和原因，允许继续保存点表或其它配置，不自动修正或删除点。允许保存不表示这些点能正常取值，配置编写人员仍须依据协议修正。

`config.toml` 的语法、字段类型和参数范围错误仍阻止保存。CSV 文件结构、通信头部、点类型与名称冲突也仍严格检查：无法解析的文件或冲突的 OPC 节点不能视为可用配置。

同串口的波特率和特殊串口模式须一致；同串口不能重复定义设备地址；完整配置中不能有重复或保留节点名等冲突。

错误包含文件名，并在可以定位时包含行号、完整点名、字段及原因。例如：

```text
rcd_example.csv: 第 83 行 EXAMPLE_AI4: byte_index=20 超出状态数据长度 1..=19
```

点地址或位范围问题会逐点列为提示；文件结构等阻断错误通常先返回该文件首个问题。提示数量和总文本有上限，超限明确说明已省略，不表示其余记录均正确。

有阻断错误时不保存、不创建本次保存备份、不改变运行配置。只有点表提示时可以保存，仍执行 revision/CAS 防覆盖、自动备份和原子替换。保存后须明确重启目标下级才生效；不自动重启。
