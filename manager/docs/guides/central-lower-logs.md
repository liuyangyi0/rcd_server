# 下级集中日志

新版 Rust 下级可把运行日志通过 HTTP 批量发送到管理程序。该通道只用于运维日志，不替代 OPC 实时数据、命令代理或下级本地滚动日志。

## 工作方式

1. 日志仍先写下级本机滚动文件。
2. logger 使用有界 `try_send` 投递到独立发送线程；串口采集不做网络和磁盘补发 I/O，也不会等待管理端。
3. 常规日志按 500 ms/100 条成批发送，`WARN`、`ERROR` 立即唤醒发送；一次最多 500 条。
4. 失败事件写入下级有界 spool，并按 1–30 秒指数退避补发。超过上限优先淘汰低等级日志；本地滚动文件不受影响。
5. 每次启动生成 `boot_id`，事件带单调 `sequence`。管理端在 SQLite 只保存 ACK 游标，日志正文按来源保存为 8 MiB 滚动 JSONL 文件；重试不会在页面重复显示。

管理端接收接口为 `POST /api/v1/lower-ingest/logs`，查询接口为 `GET /api/v1/lower-logs?source_id=...`。收到新批次后只通过 SSE 发送 `lower_logs_changed` 失效通知，不把日志正文推入浏览器全局状态。

## 配置与使用

在每个下级 `config/config.toml` 的 `[logging]` 后添加：

```toml
[logging.http_push]
enabled = true
url = "http://192.168.10.46:8087/api/v1/lower-ingest/logs"
source_id = "lower-a" # 必须与管理端来源 ID 完全一致
batch_interval_ms = 500
batch_size = 100
queue_capacity = 10000
spool_directory = "push-spool"
spool_max_bytes = 16777216
request_timeout_ms = 3000
```

重启下级后，在管理 Web 左侧进入“下级日志”，选择来源，可按等级、串口、站点和关键字过滤，并导出当前页 CSV。“刚收到推送”只表示最近有日志到达；安静运行时显示“已有历史日志”不等于连接故障。若旧筛选导致表格为空，点击“显示最新日志”会清除等级、关键字、串口、站点和分页条件，直接回到该来源的最新记录。

页面下方的“下级日志等级”显示两份状态：

- “当前运行”是本进程真正生效的等级；“已保存配置”是下次启动将采用的等级。
- 可选 `ERROR`、`WARN`、`INFO`、`DEBUG`、`TRACE`。`INFO` 是日常推荐值；`DEBUG`、`TRACE` 会显著增加文件、HTTP 推送和管理端集中日志量，只建议短时排障。
- 保存等级只修改下级 `config.toml`，不会暗中重启采集进程。两份等级不同时页面显示“需要重启”，管理员应到“下级 OPC → 运维 → 进程”明确执行重启。
- 若启动环境设置了 `RUST_LOG`，它优先于文件配置，页面会显示“环境变量覆盖”；此时需要先调整进程启动环境，仅修改 Web 配置不会改变实际等级。
- 日志等级写入使用下级配置 revision 和管理器来源 revision 双重校验；他人已修改配置时会拒绝覆盖并要求刷新。

排障时以两份数据互补：集中日志适合统一搜索；下级“运维 → 日志”直接读取本机原始文件，可核对管理端断网期间或 spool 淘汰的低等级日志。

## 命令发送次数与补发原因

“命令记录”页面下方新增“串口发送明细”，按来源选择，支持“发生补发”“发送至少 3 次”“全部发送结果”和服务端分页。它是下级串口执行记录，不是根据管理端超时或相同报文推测的次数，也不会把不同管理器/Session 的相同报文合并到一条审计。

- **发送 3 次 = 首次发送 + 补发 2 次**。次数来自完整串口写入返回成功；“尝试”另计，包括写入失败。写入失败可能已经发送部分字节，不保证设备完全没收到。
- 明细包括串口、站点、下级 ACK 编号、启动/日志批次身份、报文预览、实际发送/尝试上限、各次 ACK 超时或不匹配等原因、最终结果与串口执行耗时（不含上级排队和网络）。
- 收到 `00 50 50` 即停止该次命令的重试；补发后收到 ACK 显示“补发后成功”，仍保留前面的失败原因。未收到 ACK 显示“未获得成功确认”，不代表设备一定没有执行。
- 每条进入 worker 的带 ACK 命令在执行结束时生成一次 `rcd_server::command_audit` JSON 摘要；只保留前 256 字节报文和最后 8 次异常。排队阶段就被拒绝/过期的命令仍看上方管理端审计；进程被强杀可能没有终态摘要。
- HTTP 摘要使用原有有界非阻塞队列，不受普通 `logging.level` 过滤；不会启用原本关闭的推送。本机文本摘要仍遵循日志等级：补发或失败为 WARN，首次成功为 INFO。
- 明细与普通集中日志共用滚动保留及容量限制，不是无限期审计。HTTP 关闭、队列满、spool 淘汰、旧下级或历史命令都可能没有明细；**无明细不能判定未补发，不用 0 或 1 伪造历史次数**。旧 OPC 点表、ACK 1/2/3 和命令重试策略不变。
- 推送只到已配置的管理端。例如下级仍向 46 推送，58 不会自动获得相同明细。需要更新下级和管理端才能使用；只更新 Web 不会产生次数。

查询接口沿用 `GET /api/v1/lower-logs`，增加 `command_attempts=all|retried|three` 精确过滤；过滤在计数/分页前完成。HTTP 补传按事件身份去重，来源隔离，不按相同命令内容去重。
