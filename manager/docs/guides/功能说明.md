# RCD OPC 管理程序功能说明

按2026-10-21工作树说明功能，不是现场实时版本清单。管理端连接多个Rust下级OPC UA，将同一逻辑设备组的冗余来源合并，对外提供OPC、Web和REST，并集中执行calc.toml。现场管理OPC为4840、Web为8087、原采集下级为4841；新通信下级在46使用4842。软件分工和操作入口见[整体使用说明](../../../docs/整体软件使用说明.md)。带revision的SelectSource及数字开头状态输入已随`0.6.12-state-names.20261021.1`发布三台，具体边界见[验收记录](../validation/state-input-digit-names-20261021.md)。

## 数据接入、分组和上级 OPC 树

- 下级发布“串口 → 设备/子站 → 原始点/计算点”拓扑；管理员把各冗余来源中的对应设备绑定到同一个逻辑组。同组同名点类型和值秩一致才合并，跨组重名、类型或方法签名冲突会隔离问题来源。
- 旧 `ns=2` 业务 NodeId、BrowseName、父子引用、读写权限和发送方法保持兼容。新管理信息只位于 `ns=3`。
- 上级 OPC 客户端可 Browse：`Groups/<group>/Members/<source>/Ports/<port>/Devices/<device>`。组级 `PointNodeCount` / `PointNodeIds` 可从 KKS 精确反查逻辑组；成员级 `CoverageKnown`、`ProvidedPointNodeIds` / `MissingPointNodeIds` 可确认这个 KKS 在可选 Source 中是否兼容可用。所有 String[] 均支持标准 OPC `IndexRange` 分页；点集/覆盖的单调 Revision 与内容指纹由同一个原子不可变快照提供，组级 `CatalogRevision` seqlock 又覆盖点表和全部成员，客户端前后校验同一个非零偶数即可排除热更新跨表混代。来源节点还显示连接/目录状态、是否可选、当前 Session 是否选中，以及期望/提供/缺失点数；设备节点显示站址、名称、KKS 前缀、原始/计算点数、有效归组、是否人工绑定和是否存在于已验证拓扑快照。
- 未发现的配置占位设备使用 `AddressKnown=false`，站址值返回 `BadWaitingForInitialData`，不会用合法的地址 0 冒充未知。缓存损坏只隔离对应来源；冲突来源不可选择，但仍保留已验证物理拓扑供排障。
- 物理树热更新按稳定 NodeId 差异化增删。来源改名、Endpoint 或统计变化会原位更新，已有订阅不会因整树删除重建而短暂收到节点不存在。

## Session 级整组选源和数据质量

客户端先浏览成员树，再在同一Session调用`SelectSource(SourceId String, ExpectedRevision UInt64)`；版本冲突返回BadInvalidState，成功输出来源和新revision。旧`SelectedSourceId` String写入保留，但不携带客户端期望revision。一次选择切换本Session的整个逻辑组，不是单个KKS或所有客户端。需要独立切源的站点应先归入独立逻辑组；成员物理树只读，完整NodeId和示例见[接入说明](使用说明.md#53-推荐带revision校验的method)。

- 不同 Session 可为同组选择不同来源；`IsSelected` 的读和订阅也按 Session 隔离。Web 可以只修改指定在线 Session。
- 新 Session 复制默认源；修改默认源不影响已在线 Session。原 Session 断线重附着保留路由和订阅，Close/Timeout 后新 Session 回到默认。
- 自动故障转移默认关闭。可按组开启、按Session参与，默认源自动另有开关；包含健康确认、故障延时、冷却及命令锁，不自动回切。手动固定或无健康备用时保留原来源；该来源通信中断的原始采集点按类型清零并返回坏质量，不把正常的固定来源清零。手动选源会退出本组自动参与。差异告警独立于切源，见[自动切源说明](redundancy.md)。
- `MemberSourceIds`列出配置成员，可能离线、停用或不可选；不能当作健康列表。有效缓存的离线成员可选，但点质量仍坏。
- `Selectable=true` 表示允许选择，不等于覆盖全部并集点。应同时检查 `CompleteCoverage`；缺点来源被选中后，对应点返回 `BadConfigurationError`。

## 管理端集中计算

- 没有中央活动配置时，管理器继续转发下级计算点。激活中央配置后，管理器忽略下级拓扑中的计算点并注入自己的只读虚拟计算点，保持 `ns=2;s=<KKS>`、BrowseName、数据类型和父引用不变。
- 全局计算只按各逻辑组的默认来源取原始值，所有上级 OPC Session 看到相同结果；Session 的 `SelectedSourceId` 仅影响普通原始点。默认源改变会递增 `DefaultRouteRevision` 并重建受影响结果。
- Go 引擎兼容 Rust 的算术、比较、逻辑、位运算、移位、单目和 `IF` 语义。反向依赖索引与 10 ms 合并窗口只重算脏输入的依赖闭包；默认路由、连接状态或目录变化才执行相关全量质量重算。
- 原始采集点通信中断时先按声明类型归零，再参与中央计算。计算点保留公式的最终运算值，并沿实际执行路径传播 `BadNoCommunication`；不能只看数值判断数据是否有效。
- [状态输入](calculation-state-inputs.md)可固定物理来源或跟随组默认来源；离线状态5仍可为有效Good值，不被普通采集清零。IF未执行分支和无关来源的坏质量不污染结果。
- TOML 采用严格整版校验。重复输出、自引用、循环、缺少基础点、与原始点/命令重名、非法类型和值秩等错误不会替换上一有效版本。热删除输出在本进程中保留为 `BadOutOfService`；已发布 NodeId 的类型变化进入 `pending_restart`。
- Web“计算中心”提供实时结果、CSV 导出、大文件草稿编辑、从下级导入、错误定位、激活、不可变版本历史和回滚。SQLite WAL 保存配置版本和校验报告，不保存实时结果或历史曲线。
- `ns=3/RcdManager/Calculations` 提供活动 revision、配置 hash、规则和质量计数、默认路由 revision、最近求值耗时、待重启状态和完整计算 NodeId 数组。计算值或质量改变后，会分批强制所有在线 Session 重采样。
- 下级新增 `local/manager` 双模式。`local` 完全保留单机行为；`manager` 不解析或执行本机公式，也不创建计算 OPC 节点，但保留 `calc.toml` 文件 hash、规则数量和回滚副本。切换模式只保存配置并返回待重启，不会自动重启，也不会丢失现场注释。

## 命令、下级采集和进程管理

- `_Send`/组`Send` String写入在接受时固定Session、来源、物理串口和epoch，按端口FIFO处理，最多64条（含执行中）；Write Good只表示管理端接受，不代表下级已接收或设备已完成。同步`SendCommand`不排队，等待ACK终态，只有Good和Result="1"表示协议确认，不保证动作反馈已核实。排队与执行期间锁定相关组选源；结果不明不重投、不换源，逐条结果看[命令审计](command-tracking.md)。
- 下级采集运维按物理来源执行，不跟随上级Session选源。可开关串口、停启单站读取，显示期望、已应用、串口是否打开和实际通信；操作与同串口命令互斥。保存的开关持续有效，不会自动还原为操作前值。
- 每个物理站点可配置为未知、国产或俄供通信模块。未知和俄供不发送版本命令；国产在启动、重新启用或改为国产后查询一次，也可由 Web 手动刷新。通信模块/PLC 版本、原始载荷、实测类型、不一致和历史状态会持久化，并通过管理 Web、REST 和 `ns=3` 来源树同时提供；它不参与 KKS 合并或 Session 选源。
- 可读取和保存受限配置文件、查看分页日志，并集中查看 HTTP 推送日志。Web 可查看下级当前运行与已保存日志等级，按 `ERROR/WARN/INFO/DEBUG/TRACE` 修改配置；修改采用 revision/CAS，明确标记待重启且不会自动中断采集。`RUST_LOG` 覆盖、HTTP 推送状态和来源 ID 都会直接显示。
- Linux的RCD Agent守护固定的一份原采集进程，提供状态、输出及安全生命周期。管理网页仅对支持该能力的Agent开放启停：先关闭命令准入、排空，再SIGTERM并确认退出；超时不自动强杀，保留原作业待确认，不回退无保护启停。停止Agent自身是另一边界，可能连带其下级，不应代替普通站点排障。
- 进程作业使用稳定request_id、持久状态和共享宿主机运维互斥。人为停止意愿保留，升级不擅自拉起；配置保存不自动重启。Agent离线时由平台独立Ansible/systemd恢复，不属于OPC自动切源。

## 新通信与软件运维平台的边界

- 新通信程序使用原名`DATA.*`、UInt32 Fire编号、定长十六进制String及TransmitSnapshot整包CAS；发送最新快照，不进入控制命令FIFO，不等待00 50 50 ACK。支持5秒刷新/15秒过期的可配置要求，变量及示例见[通信客户端说明](../../../communicate/docs/opc-client-guide.md)。
- 当前新通信程序只在46停用串口接入，真实角色/串口及物理收发未验收；未接入原采集Agent安全生命周期或平台三组件一键发布，不能照搬这些按钮。
- Semaphore＋Ansible负责原采集、管理端、Agent的软件包升级与兼容恢复，并安全启停管理端；管理网页经Agent负责原采集日常启停。平台停止不停止现有采集；平台也不同步三台管理端的业务计算与选源配置。

## Web、容量与验收边界

Web 提供总览、组/来源配置、串口设备映射、在线 Session、手动整组选源、分页点位、设备版本、双源比较、命令/管理审计、告警、下级运维、配置和日志。下级日志可由独立 HTTP 线程批量推送并在管理端按来源集中滚动保存，断网使用有界磁盘 spool 补发且绝不阻塞串口；原下级文件读取继续作为完整日志兜底。上限为 20 个下级、10 个上级 Session；高频点值保留在内存，SQLite WAL 只保存配置、目录、站点版本缓存、日志 ACK 游标和审计，不保存日志正文。

本功能摘要不是当前部署清单，也不重新声明历史测试项数、点数或长测通过。各批次版本、测试命令、部署范围和未验收项见[验收索引](../README.md#测试与历史验收)，实际运行版本及点数以当前网页/运行映像为准。

20×约5300点、10个全量上级订阅及长期延迟指标是独立性能验收场景，不能由配置上限或本次文档审查推导通过。Linux服务部署与Windows服务验收分别核实；不将一台机器或旧版本的结果外推为所有平台当前均通过。
