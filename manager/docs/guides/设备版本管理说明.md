# 国产/俄供通信模块版本管理

## 使用入口

打开管理程序 Web 后进入“数据 → 设备版本”。这里按“下级来源 → 物理串口 → 站点”列出设备，不受 OPC 分组默认源或客户端 Session 选源影响。同名点位来自多个下级时，版本信息也不会合并。

页面顶部按来源去重汇总下级 RCD 软件版本和构建提交；表格同时显示模块配置类型、实测类型、通信模块版本、PLC 版本、最近查询时间和错误。页面中的十六进制原始值可用于与现场抓包核对。下级离线时仍显示最后缓存，但会标记“离线缓存”或“已过期”。

旧版下级没有 `station_versions` 能力时会明确显示“下级版本功能不支持”，类型设置、勾选和版本查询均被禁用；升级下级不会影响它原有的 OPC 数据采集。

## 配置模块类型

1. 勾选一个或多个站点，单击“批量设置类型”；也可在站点行内单击“设置类型”。
2. 选择类型：
   - `国产自研模块`：允许发送版本查询。保存后，下级会在正常轮询的安全间隙自动查询一次。
   - `俄供原模块`：不发送版本查询。
   - `未配置`：不发送版本查询，适合尚未核实的既有站点。
3. 配置为国产时必须再次勾选确认，避免向俄供或未知设备误发命令。

批量修改按下级来源串行执行，同一来源内不会用旧 revision 继续写入；某来源的一项失败后，该来源剩余项停止执行，其他来源继续。每行会保留本次执行结果。

## 手动查询版本

只有同时满足以下条件的站点可以使用“查询版本”：

- 已明确配置为国产模块；
- 下级 OPC 在线；
- 串口启用配置已经应用且串口实际打开；
- 站点读取配置已经应用；
- 串口没有待处理控制或命令。

查询会插入正常采集轮询之间，同一物理串口严格串行。单次查询超时不会自动重试；历史成功值会保留并标记过期。若国产配置返回俄供特征，页面显示“类型不一致”，不会自动改写人工配置。

## OPC 客户端查看

外部 OPC UA 客户端仍连接管理端 `opc.tcp://<管理机>:4840`。版本信息位于管理命名空间的来源树：

```text
Objects
└─ RcdManager
   └─ Sources
      └─ <source_id>
         └─ Ports
            └─ <port>
               └─ Devices
                  └─ <device_id>
```

节点提供配置/实测类型、通信模块版本、PLC 版本、原始值、查询状态和时间。它们均为只读，并始终对应明确的下级物理站点；切换某个 OPC Session 的业务数据源不会改变这棵树。配置类型和触发查询必须在 Web 中操作。

管理命名空间固定为 `ns=3`。例如串口 `/dev/ttyWCH0` 在字符串 NodeId 中会进行 URL 转义，站点 11 的通信模块版本 NodeId 为：

```text
ns=3;s=Sources/<source_id>/Ports/%2Fdev%2FttyWCH0/Devices/11/CommunicationModuleVersion
```

来源节点还提供 `RcdSoftwareVersion`、`RcdBuildCommit` 和 `StationVersionRevision`。版本节点质量含义如下：有效国产版本为 `Good`；未查询为 `BadWaitingForInitialData`；人工配置俄供为 `BadNotSupported`；类型不一致为 `BadConfigurationError`；离线但有历史值为 `UncertainLastUsableValue`；离线且无历史值为 `BadNoCommunication`。

## 状态解释

| 状态 | 含义 |
|---|---|
| 版本有效 | 国产模块返回有效四字节版本载荷 |
| 未配置 / 等待首查 | 尚未允许查询或国产站点等待第一次查询 |
| 俄供·不查询 | 人工配置为俄供，管理系统不会发送版本命令 |
| 类型不一致 | 配置为国产，但完整有效响应表明为俄供 |
| 查询失败 | 超时、坏帧或校验失败；不会覆盖最后成功版本 |
| 已过期 / 离线缓存 | 当前无法确认，显示的是最后一次成功数据 |

需要留档时使用“导出当前页 CSV”；先用筛选条件缩小来源、串口、类型或状态范围。
