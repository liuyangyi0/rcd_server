# 组内自动切源与数据差异告警

两个功能默认关闭，互相独立。在“分组与选源”点击组名下的“自动切源 / 差异告警”配置。保存需要勾选物理设备对应关系及控制影响确认，旧版本请求返回 409，不覆盖其他人的修改。

## 自动切源

按优先级添加至少两个本组来源。默认故障确认 5 秒、备用正常确认 5 秒、切换冷却 30 秒。后台每秒检查一次，底层站点状态采集也有刷新周期，因此设置时间不是硬实时切换承诺。

来源必须启用、OPC 连接/Session/订阅可用、目录无冲突且覆盖本组所有原始采集点。每个对应站点的实际通信状态必须正常、属于当前连接及拓扑且未过期；原始点须收到当前连接的 Good 样本。组内任一采集站停读、串口未打开、坏质量、缺点或没有站点状态能力，均不能成为健康备用。只看 OPC 连通是不够的；值一直不变也不表示掉线。

开启后新 Session 默认参与自动切源；已有 Session 不被强行接管，请在弹窗“在线 Session 参与方式”逐个选“跟随自动”。手动写 `SelectedSourceId` 或原手动选源操作会使该 Session 本组回到“手动固定”。短暂重连恢复原 Session 保留方式，新 Session 使用当时组策略。关闭组开关暂停自动动作，不改当时来源；之后重新开启会恢复仍选择“跟随自动”的在线 Session。

异常持续达到阈值且有经过正常确认的候选时，整个逻辑组切到最高优先级健康来源。没有健康备用则保持原选择并显示原因；不会从坏来源中随便选一个。当前来源恢复后不自动回切。未设置来源时不自动补默认值，先通过现有界面设置来源。

“组默认来源也自动切换”单独控制默认源及中央计算，默认不勾选。勾选且自动切源总开关开启后，默认来源故障也会按同一规则切换并触发中央计算重算；它不会改变手动固定的在线 Session。

自动切源不改变 KKS NodeId。成功后刷新目标 Session 现有订阅，即使新旧值相同也刷新。任何本组命令等待 ACK 时禁止切源、修改策略或参与方式；已经开始的命令不重投，不改变目标。切源后的新命令才使用新来源。

## 差异告警

选定本组两个来源，设置持续时间、数值绝对/相对容差及允许的源时间差。只比较同名标量原始采集点，排除命令、下级计算和中央计算；中央计算只有一份共享结果，不能据此做双来源独立比较。

本版本采用保守规则：两个来源都须满足上述整组健康条件。来源异常、任一点坏质量、缺失源时间、源时间差过大或样本连接 epoch 失效时，相应数据不可比较，不把断线清零当成差异。下级时钟应同步；静态点的源时间差也可能导致跳过，需按现场时间语义设置允许差值。

数值差异超过 `max(绝对容差, 相对容差 × max(|左值|, |右值|))` 才计为不同；相对容差 0.01 表示 1%。Boolean/String 直接比较。每点分别计时，中断、恢复相同或换连接后重新确认，不累计断断续续的差异。

- `Different`：有达到持续阈值的差异，写入告警中心，按组汇总并显示前 20 个点的双方值和持续起点。
- `Confirming`：发现差异但尚未达到确认时间。
- `Equal`：整组所有参与点均可比较且一致，恢复旧告警。
- `Unknown`：部分或全部不可比较；原告警保持，不误标为已恢复。
- `Disabled`：未开启或已关闭检测；明确关闭会结束旧告警。

告警支持现有确认、静默和历史查看。不把高频值写数据库；只在告警内容/状态变化时落库。仅两个值不一致无法判断谁正确，绝不据此自动切源。

## OPC 与接口

`ns=3;s=Groups/<组ID>/` 下新增：

| 节点 | 类型及含义 |
| --- | --- |
| `AutomaticSelection` | Boolean，按当前 Session 读写；true 参与自动，false 手动固定；组策略未开启时不能写 true |
| `AutoSwitchEnabled` | Boolean，只读组自动开关 |
| `DefaultAutomatic` | Boolean，只读默认源自动策略是否实际启用 |
| `DataDifferenceAlarmActive` | Boolean，只读尚未恢复的差异告警，重启后保留 |
| `DataDifferenceCount` | UInt32，最近一次检测已确认的差异点数量；不可比较时不能仅凭 0 判断告警已恢复 |
| `DataComparisonState` | String，上述检测状态 |
| `LastAutoSwitchReason` | String，本进程最近切源原因；完整历史看管理审计 |

这些诊断节点的 Good 表示判断/配置可读，是否正常仍看 Value 和检测状态。除 Session 自己的参与方式外，策略只能在 Web/REST 配置。

- `GET/PUT /api/v1/groups/{id}/redundancy`：读取状态或保存策略；PUT 同时检查正文 revision 与 If-Match。
- `PUT /api/v1/sessions/{session}/groups/{group}/automatic`：正文 `{ "automatic": true, "revision": 3 }`，If-Match 同为 3。已结束 Session 返回 404，命令锁和版本冲突返回 409。
- SSE `redundancy.changed` 使策略查询失效；自动切源沿用 `selection.changed`，告警沿用 `alarm.changed`，不推送整张实时点表。

组策略存入 SQLite 并纳入配置导出。导入时恢复参数但强制关闭自动切源和默认源自动开关，待人工确认设备映射后开启；差异检测保留导入设置。导入仍遵守原来的“仅空配置可恢复”限制。组删除同时清理策略并恢复该组的未结束差异告警，历史记录保留。
