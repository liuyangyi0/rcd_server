# 在计算中心使用站点通信状态

## 使用方法

打开管理 Web 的“计算中心 → 状态输入”。无需填写 OPC 路径，也无需输入 `%2F` 等转义字符。

1. 点击“新增状态输入”，给站点状态起一个英文变量名，例如 `WCH0_11_STATE`。
2. 选择取源模式、来源、串口和站点。串口直接选 `/dev/ttyWCH0`，站点选 `11`。
3. 保存为草稿。在“规则配置”中编写引用该变量的公式，校验并激活后才生效。
4. 回到“状态输入 → 当前生效”，检查实际来源、状态数值和观测时间；到“实时结果”查看公式结果。

保存状态输入会规范化整份草稿 TOML 的排版并移除注释，原规则字段值保持不变。页面要求勾选确认；需要保留注释时，请先复制备份原始文本。

## 两种取源方式

“固定来源”：始终查看指定下级的指定站点。适合同时监视三台下级，或分别生成各台下级的报警。

“跟随组默认来源”：按该组的全局默认来源选择对应站点。需为每个来源选择站点；各来源可以使用不同串口和站号。“按已选站点匹配其他来源”只能匹配串口名和站号相同的站点，保存前应核对。

只有修改组的**默认来源**才会改变第二种方式的目标。OPC 客户端自己的 Session 选源不改变计算结果。管理计算结果始终由所有 OPC 客户端共享。

## 状态值怎样使用

| 数值 | 含义 |
| --- | --- |
| 0 | 未获取、切换中或状态已过期 |
| 1 | 通信正常 |
| 2 | 通信异常，例如超时或没有有效数据 |
| 3 | 串口未打开 |
| 4 | 串口或站点已停用 |
| 5 | 下级 OPC 离线 |

这些是变量的数值，不是 OPC 质量码。有效状态的质量为 Good，包括数值 2、3、4、5。这样下级离线时，公式仍能使用 `5` 判断离线，不会被普通采集点的断线清零逻辑变成 `0`。

配置的来源、组或站点不存在，或者默认来源没有对应映射时，则是配置错误，返回 `BadConfigurationError`，不能当成有效的“未知状态”。

例如，正常输出 0，其他状态输出 1：

```toml
[[rules]]
kks_calc = "WCH0_11_ALARM"
data_type = "UInt32"
expression = "IF(WCH0_11_STATE == 1, 0, 1)"
```

仅当下级离线时输出 1：`IF(WCH0_11_STATE == 5, 1, 0)`。

要让 OPC 客户端读取原始状态数值，也可以创建一条计算规则，表达式只填 `WCH0_11_STATE`。假如输出名为 `WCH0_11_STATE_OUT`，OPC 节点为 `ns=2;s=WCH0_11_STATE_OUT`。状态输入别名本身不是新增的业务 OPC 节点。

## 配置文本示例（可选）

通常通过页面选择即可。以下配置的含义是：把来源 `real-lower` 的 `/dev/ttyWCH0` 串口、11 号站点状态命名为 `WCH0_11_STATE`。

```toml
[[state_inputs]]
name = "WCH0_11_STATE"
mode = "fixed"

[[state_inputs.targets]]
source_id = "real-lower"
port_id = "/dev/ttyWCH0"
device_id = "11"
```

`source_id` 是管理器配置的来源 ID，不是 IP，也不是可以随时修改的显示名称。别名只能使用英文字母、数字和下划线，不能以数字开头，不能与原始点或计算输出重名。

## 修改、回滚和排错

- 编辑和删除在“已保存草稿”视图中进行；不会立即影响当前计算。删除仍被公式引用的别名后，必须同时修改引用公式，否则校验不能通过。
- 两个人同时保存时，旧版本请求返回冲突，不覆盖另一人的修改。取消编辑、刷新草稿后重新修改。
- “实时结果”的依赖展开区可以查看公式直接或间接使用的状态输入和实际站点。
- 状态观测超过 15 秒未更新会变成 0；新连接必须取得本轮连接的快照，不能沿用旧连接的“正常”。
- 状态输入与规则一起保存为计算版本。版本历史回滚会创建新版本；原历史不改写。
- 新增来源后，跟随默认来源的映射需要补全。修改配置时会校验全部候选来源，缺少映射不能激活。

接口：`GET /api/v1/calculations/state-inputs`（支持 `view=active/draft`、分页、搜索、模式、实际来源、状态和规则依赖筛选）；`GET /api/v1/calculations/state-input-candidates` 获取可选站点。草稿仍使用原保存、校验和激活接口及 revision 校验。
