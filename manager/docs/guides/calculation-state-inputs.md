# 在计算中心使用站点通信状态

状态输入同名 OPC 输出已于2026-10-23随 `0.6.18-state-output.20261023.1` 部署到30、58、46，见[验收记录](../validation/state-output-deployment-20261023.md)。

## 使用方法

打开管理 Web 的“计算中心 → 状态输入”。无需填写 OPC 路径，也无需输入 `%2F` 等转义字符。

1. 点击“新增状态输入”，给站点状态起一个英文变量名，例如 `WCH0_11_STATE`。
2. 选择取源模式、来源、串口和站点。串口直接选 `/dev/ttyWCH0`，站点选 `11`。
3. 保存为草稿，在“规则配置”中校验并激活。状态输入会直接生成同名 OPC 输出点，无需编写转发公式；也可在其他公式中引用它。
4. 回到“状态输入 → 当前生效”，检查实际来源、状态数值和观测时间；到“实时结果”查看公式结果。

保存状态输入会规范化整份草稿 TOML 的排版并移除注释，原规则字段值保持不变。页面要求勾选确认；需要保留注释时，请先复制备份原始文本。

## 两种取源方式

“固定来源”：始终查看指定下级的指定站点。适合同时监视三台下级，或分别生成各台下级的报警。

“跟随组默认来源”：按该组的全局默认来源选择对应站点。需为每个来源选择站点；各来源可以使用不同串口和站号。“按已选站点匹配其他来源”只能匹配串口名和站号相同的站点，保存前应核对。

只有修改组的**默认来源**才会改变第二种方式的目标。OPC 客户端自己的 Session 选源不改变计算结果。管理计算结果始终由所有 OPC 客户端共享。

## 状态值怎样使用

| 数值 | 含义 |
| --- | --- |
| 0 | 未获取、切换中或状态已过期 |
| 1 | 通信正常 |
| 2 | 通信异常，例如超时或没有有效数据 |
| 3 | 串口未打开 |
| 4 | 串口或站点已停用 |
| 5 | 下级 OPC 离线 |

这些是变量的数值，不是 OPC 质量码。有效状态的质量为 Good，包括数值 2、3、4、5。这样下级离线时，公式仍能使用 `5` 判断离线，不会被普通采集点的断线清零逻辑变成 `0`。

配置的来源、组或站点不存在，或者默认来源没有对应映射时，则是配置错误，返回 `BadConfigurationError`，不能当成有效的“未知状态”。

例如，正常输出 0，其他状态输出 1：

```toml
[[rules]]
kks_calc = "WCH0_11_ALARM"
data_type = "UInt32"
expression = "IF(WCH0_11_STATE == 1, 0, 1)"
```

仅当下级离线时输出 1：`IF(WCH0_11_STATE == 5, 1, 0)`。

激活后，每个状态输入直接发布为 `Objects/Devices/<name>`，NodeId 为 `ns=2;s=<name>`，类型为 UInt32，只读，可 Read、Browse 和 Subscribe。例如 `WCH0_11_STATE` 对应 `ns=2;s=WCH0_11_STATE`，无需另写转发公式。状态变化、质量变化、过期和默认来源变化都会更新输出，所有 Session 读取相同的状态。

已有不同名称的转发公式继续有效。不要再创建与状态输入同名的 `[[rules]]` 输出，否则校验会报告重名。删除状态输入后，该进程内旧节点返回 `BadOutOfService`；重新添加同名 UInt32 状态输入可热恢复，重启后清除已删除节点。公式数量和公式质量统计仍只统计 `[[rules]]`，状态输入在“状态输入”页查看。

## 配置文本示例（可选）

通常通过页面选择即可。以下配置的含义是：把来源 `rcd-46` 的 `/dev/ttyWCH0` 串口、11 号站点状态命名为 `WCH0_11_STATE`。

```toml
[[state_inputs]]
name = "WCH0_11_STATE"
mode = "fixed"

[[state_inputs.targets]]
source_id = "rcd-46"
port_id = "/dev/ttyWCH0"
device_id = "11"
```

`source_id`是管理器配置的来源ID，不是IP或可修改的显示名称。别名最长128字符，只能使用英文字母、数字和下划线，**允许数字开头**，但不能是纯数字或IF/true/false（不分大小写），也不能与其他状态输入、原始点或计算输出重名。该支持已于2026-10-21随`0.6.12-state-names.20261021.1`部署到30、58、46；其他旧版本仍可能拒绝，详见[部署记录](../validation/state-input-digit-names-20261021.md)。

例如，固定读取58来源的WCH0、11号站点，可以直接使用原名称，不必加前缀：

```toml
[[state_inputs]]
name = "9CYE91GH201_COM1"
mode = "fixed"

[[state_inputs.targets]]
source_id = "rcd-58"
port_id = "/dev/ttyWCH0"
device_id = "11"

```

本例直接发布`ns=2;s=9CYE91GH201_COM1`，不需要`[[rules]]`。实际IP取决于管理端中rcd-58的Endpoint配置，串口和站点须存在于该来源拓扑。该直接输出行为需要支持状态输入发布的新版管理端；旧版仅将它作为公式内部别名。

## 修改、回滚和排错

- 编辑和删除在“已保存草稿”视图中进行；不会立即影响当前计算。删除仍被公式引用的别名后，必须同时修改引用公式，否则校验不能通过。
- 两个人同时保存时，旧版本请求返回冲突，不覆盖另一人的修改。取消编辑、刷新草稿后重新修改。
- “实时结果”的依赖展开区可以查看公式直接或间接使用的状态输入和实际站点。
- 状态观测超过 15 秒未更新会变成 0；新连接必须取得本轮连接的快照，不能沿用旧连接的“正常”。
- 状态输入与规则一起保存为计算版本。版本历史回滚会创建新版本；原历史不改写。
- 恢复管理端旧二进制是另一回事：激活数字开头名称后，不能只凭数据库schema相同恢复到不支持该名称的旧程序。须先在当前版本改为兼容名称、更新引用并校验激活，或选用包含本修复的版本；不要覆盖当前数据库来规避校验。
- 新增来源后，跟随默认来源的映射需要补全。修改配置时会校验全部候选来源，缺少映射不能激活。

接口：`GET /api/v1/calculations/state-inputs`（支持 `view=active/draft`、分页、搜索、模式、实际来源、状态和规则依赖筛选）；`GET /api/v1/calculations/state-input-candidates` 获取可选站点。草稿仍使用原保存、校验和激活接口及 revision 校验。
