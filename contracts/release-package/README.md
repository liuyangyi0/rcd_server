# RCD 单组件发布包 v1

适用于 Semaphore 原生定制版，不依赖 Mender。扩展名为 `.rcd.tar.gz`。

归档使用单个 gzip 数据流、USTAR 格式，仅有两个根目录普通文件：

- `manifest.json`：UTF-8 JSON，最多 64 KiB，拒绝未知字段、重复 JSON 键。
- `binary`：Linux 64 位 little-endian ELF 可执行文件，最多 512 MiB。

压缩包最大 256 MiB。禁止目录、链接、PAX/GNU 扩展头、重复成员、其他文件以及尾随非零数据。控制器不运行上传文件。实际运行身份必须在发布后另外确认。

清单必需字段：

| 字段 | 含义 |
| --- | --- |
| `schema_version` | 固定 1 |
| `component` | `lower`、`manager`、`agent`、`communicate`（独立串口同步通信程序），或本项目事先注册的额外软件标识 |
| `version`、`release_id` | 显示版本及不可覆盖的发布编号；1–128 个 ASCII 字母、数字、点、下划线、加号或连字符，以字母/数字开头，与现有构建标识规则一致 |
| `commit` | 40 位小写十六进制源码提交 |
| `source_sha256` | 64 位小写十六进制构建源码摘要，包含已记录的未提交修改 |
| `dirty` | 构建是否包含未提交修改，不隐藏脏工作区 |
| `built_at` | 带时区的 RFC3339 时间 |
| `target` | 保留实际构建报告：Go 为 `linux/amd64`、`linux/arm64`；Rust 为 `linux/x86_64`、`linux/aarch64`；均核对 ELF 头，比较兼容性时归一化架构 |
| `binary_sha256`、`binary_size` | 程序摘要及字节数 |
| `compatibility.adapter_min_version` | 三段数字最低发布适配器版本 |
| `compatibility.state_formats` | 各持久化格式的 `{min,max}` 范围，非负整数且 min ≤ max；lower 必须包含 `command_journal` 和 `maintenance`，manager 包含 `manager_db`，agent 包含 `agent_state`；communicate 与已注册额外软件必须显式为 `{}`，不接受`null`、缺字段或继承下级/管理端格式 |
| `compatibility.component_min_versions` | 其他组件的最低三段数字版本映射，可为空；不能引用自己 |
| `release_notes` | 公开说明，最多 16 KiB UTF-8，不得包含秘密 |

包内不得包含现场配置、数据库、日志、密码、PKI、安装目录或执行命令。构建完整清单中的源码文件路径不进入公开清单。

`state_formats` 中的 SQLite 格式版本指实际 `PRAGMA user_version`，不是记录内容里的 `schema_version`。例如当前下级命令审计库为 1，维护库虽保存 `schema_version=1` 的记录，其 SQLite `user_version` 为 0，因此维护库兼容声明应匹配 0。打包前应核对所选软件真实支持的格式和平台读取的目标格式，不为匹配软件包修改现场数据库版本。上传错误声明后，停用候选包并用新的构建身份出包，不覆盖原发布编号、不绕过兼容校验。

相同项目、组件、发布编号、相同解析后清单及程序摘要视为重复上传，返回已有记录（gzip 时间戳不同不导致重复发布）。不同内容返回 409。校验通过仅表示归档及摘要自洽，不等于可信签名、已经部署或实际运行版本。首版受信内网由有项目资源管理权限的账号上传。

额外注册软件还要求同一程序SHA对应唯一构建身份：不能仅更改版本、发布编号或构建来源，将相同程序重复登记成不同版本；此时409并提示复用已有包或重新构建，避免实际运行SHA匹配到相互矛盾的版本。

数据库只记录元数据和审计；包目录保留归档、公开清单及程序。上传不排队执行任务，不自动部署。停用使用 revision；不提供删除历史软件包的接口。

## communicate 的发布边界

它不是采集下级的另一种名称，也不由原采集Agent守护。安装profile必须明确绑定独立的`rcd_communicate`可执行文件及`rcd-communicate.service`，不能复用`lower` profile、管理端维护socket或Agent进程控制接口；共享同一宿主发布锁，因此不会和其他组件同时替换。

当前通信程序没有可验证的活动发送排空接口。首版仅接受**服务已确认停止**的安装/历史版本恢复，完成后保持停止；运行中、自动重启中、服务缺失、状态未知均拒绝且不自动停止。磁盘配置写了`enabled=false`不能证明进程内没有在途发送，不可据此绕过。30/58尚未安装通信程序时显示“未安装”，不借升级任务暗中创建服务。将来支持活动通信安全升级须另增并验收维护准入能力。

标准包仍只含`manifest.json`和`binary`。例如通信包的清单声明为`component="communicate"`、`target="linux/x86_64"`，兼容段为：

```json
{
  "adapter_min_version": "1.1.0",
  "state_formats": {},
  "component_min_versions": {}
}
```

这只是兼容字段示例，不是可上传的完整清单。构建工具仍核对完整来源摘要、`version --json`报告、程序SHA及ELF架构；不得给来源不明的旧二进制伪造构建身份。现场CSV、TOML、state、PKI和日志不随包替换，恢复也不覆盖当前配置。

## 注册额外软件

“添加软件种类”和“上传这个软件的新版本”是两件事。项目管理员先在软件包页面注册种类，再上传版本；注册本身不安装、不启停，也不执行任何上传内容。每个项目最多32种额外软件。

`GET /api/project/{project_id}/rcd/applications`只返回额外软件定义，内置四组件继续保留。`POST`只接受：

```json
{
  "component": "weather-reader",
  "name": "气象数据程序",
  "arguments": ["--listen=127.0.0.1:9100"],
  "graceful_shutdown_confirmed": true
}
```

标识为1–32位小写字母、数字和短横线，以字母开头；内置组件、`rcd-`前缀及系统保留名称不可注册。名称最多80字。启动参数最多16项、总计2048字节，不支持shell、环境变量、systemd展开或`..`路径跳转。管理员确认软件支持SIGTERM正常退出；这不等于平台知道该软件的设备事务是否已经排空。

服务端固定生成`/opt/rcd/apps/<标识>/bin/<标识>`、工作目录`/var/lib/rcd/apps/<标识>`和用户级`rcd-app-<标识>.service`，使用主机已登记的非root用户；浏览器和发布包不能更改路径、服务名、用户、环境变量或脚本。定义创建后不改写；完全相同的重复请求返回200，不同内容返回409，首次注册201。上传和发布均再次验证项目注册，其他项目的注册不能授权本项目使用该软件。

额外软件只支持单个Linux ELF，包仍只有清单和二进制。版本来源于有权限人员上传的清单及实际进程映像SHA匹配，不要求第三方程序实现RCD的`version --json`，上传和暂存不执行它。不能把清单自洽当成代码签名或行为可信。

`state_formats={}`只表示发布器没有该应用的数据格式检查器，**不证明第三方数据库或配置天然向后兼容**。构建/发布人员须先验证新旧程序均可读取当前数据，再将版本纳入此单二进制升级/恢复流程；未验证或破坏性数据迁移不在本功能支持范围。恢复只换程序并保留当前数据，不能用覆盖旧数据库来假装兼容。

空白主机首次安装由独立原生任务完成，保持停止/待配置，不隐式启用软件或串口。后续升级/恢复只接受已绑定相同项目、定义摘要、固定路径及保护属性的服务；升级时正常停止，不强杀，超时即停止流程。自动恢复只恢复二进制，不覆盖配置、数据、维护身份；首版不承接破坏性数据格式升级。`SendSIGKILL=no`、固定30秒停止超时、无额外脚本/服务drop-in均需通过安装时检查。

完成必要配置后，从设备组件详情明确“启动软件”；启动、停止、重启仍走原生服务任务、幂等编号及相同宿主机锁，不需要选择发布包。首次明确启动才启用用户服务自启动（主机还须具备正常的用户systemd会话/管理员设置的linger）；人为停止写入持久停止标记，即使主机重启也不会擅自恢复，再次明确启动后才解除。页面说明这是进程级正常启停，不是硬件事务排空。`communicate`不属于这一通用启停入口，不能通过换名称绕过其停机限制。

首装完成但尚未启动的包不直接作为已验收恢复点；之后同设备、同组件通过原生启动/重启任务精确验证该SHA正在运行，首次版本才出现在历史中。失败、未知、迟到的未确认结果不计入。额外软件升级在停止和替换前持久设置启动保护；原有人工停止标记不覆盖，已捕获的未知启动结果保留保护和原作业，不自动重投。
